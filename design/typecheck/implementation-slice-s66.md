## Phase 4 refresh notes (2026-05-11) — Wave 3a-α redo under corrected inputs

User-arbitrated architectural correction (commits `ab1686c..f7f4287`, 2026-05-10/11) reversed three contested inputs that the first Wave 3a-α attempt (commit `ab068e2`, 2026-05-13) had baked in. The slice is refreshed to guide the **α redo** under the corrected inputs:

- **Decision 45 reversal: Pattern A → Pattern B.** TraitImpl entries are now written to the **trait's defining module**, NOT the writer's module. Lookup is per-symbol **chain-follow** along the trait member's `ModuleEntry::Import` / `ModuleEntry::Reexport` binding back to the trait's home module; probe that one module for the synthetic `impl$FQTypeName$FQTraitName` key. No graph traversal; no closure walk; no cycle detection. The same chain-follow primitive serves read-side discovery and write-side target selection — symmetrical.
- **Chain-follow is THE navigation primitive.** Closure walks over the import graph (a `transitive_import_closure(module) → Set<ModuleFullPath>` function or equivalent shape) are **forbidden** per Principle 17. α's first pass introduced exactly such a function in `crates/cranelisp-typecheck/src/checker.rs`; the redo replaces every call site with per-symbol chain-follow along `source.module` references along `ModuleEntry::Import` / `Reexport` entries, terminating when a non-`Import`/non-`Reexport` (canonical) entry is reached. The chain is finite by structure (each `source.module` reference points to a strictly different module, terminating at the canonical home); no `HashSet visited`, no "bounded by loaded module count" cycle defence is required.
- **Short-name resolution is current-module-only.** A short name `foo` resolves by lookup in the **current module's `SymbolTable` only**. If `foo` is absent locally, the lookup fails. There is no fallback to other modules — no root sweep, no implicit primitives sweep, no closure walk. Universally-feeling symbols (`Int`, `+`, `not`) reach user code because the **prelude** (spec §8.8.1) injects per-symbol `ModuleEntry::Import` bindings; those bindings carry the reach, not the resolver. Special forms (`if`, `let`, `match`, …) never enter resolution — they are recognized by the parser/expander and lowered into AST nodes before any name lookup runs. The "root module" at path `""` is notional only; no `SymbolTable` instance exists at that path. This replaces α's first-pass "current_module + Import-following + closure walk" fallback chain with "current_module symbols only" — the chain-follow does the cross-module reach **per-binding**, not per-resolver.
- **Synthetic modules have empty `imports` / `exports` by invariant.** `primitives` and `macros` are compiler-seeded synthetic modules with no source forms; their `imports` and `exports` are empty `Vec`s by construction. α's first pass defensively injected `(import [macros [*]])` into `primitives.imports` (a workaround for the closure-walk path under Pattern A, when primitives' `Trace` ADT had to reach `macros/SList` via the import set). The redo **removes the synthetic glob** and constructs every cross-synthetic-module type reference **fully-qualified at registration time** (`Type::ADT(macros_fqtn("SList"), …)`). No short-name lookup ever runs from a synthetic module's bounded context.
- **Wave 3a splits into α (locality refactor) + β (triad implementation)** per Decision 46. α is a typecheck-internal sweep with no facade impact, ~3–5 days; β is the cluster-atomic triad (frontend `build_form` + typecheck `check_form_signatures`/`check_form_body` + int `process_cluster` + `ClusterContext`), ~3–4 days, atop the locality-correct typecheck. β cannot start until α completes: an orphaned `self.modules.X` pierce would read live during cluster mode (ignoring staging) and silently weaken Decision 44's cluster-atomic guarantee.
- **Open question Q2 (post-Gap state contract, prior FIXME 0160) is RESOLVED by Decision 44 + FIXME 0167.** Pass functions are pure with respect to **live state**; staging mutation flows through `ctx.current_symbol_table_mut()` (same accessor as committed-mode). On Gap, the orchestrator retries the same pass with the same `ParsedEntry` — staging may carry partial writes which the retry overwrites. On `TypeError`, the orchestrator drops staging on the floor. The slice no longer carries Q2 as an open item; FIXME 0160 is closed in spirit by Decision 44's amendment.

## 1. Scope from facade — delta table

### Section 1.A — Wave 3a-α (locality-correctness refactor; Decision 46)

The four principled access-pattern shapes per Principle 17 (the catalog α encodes; verbatim from `facades/typecheck.md` §"Bounded-context invariants" item 10):

1. **Unqualified short-name lookup** — `ctx.current_symbol_table().lookup(&name)` against the **current module only**. If the entry is `ModuleEntry::Import { source: FQSymbol, .. }` or `ModuleEntry::Reexport { source: FQSymbol, .. }`, **chain-follow** `source.module` one edge at a time, repeating the per-key lookup at each step, until a canonical (non-Import / non-Reexport) entry is reached. If the name is absent from the current module's table, the lookup **fails** — no fallback to other modules, no root sweep, no implicit-primitives sweep. Special forms never enter this path. Universally-feeling symbols (`Int`, `+`) are reachable because the implicit prelude injection of per-symbol `ModuleEntry::Import` bindings (spec §8.8.1) has already placed a binding in the current module's table during module setup.
2. **Qualified (FQ) lookup** — `symbol_tables.get(&fq.module).and_then(|t| t.get(&fq.symbol))`. Direct, single named module. No chain-follow needed; the path is explicit.
3. **Impl resolution via trait-home chain-follow (Decision 45 Pattern B)** — given a `(Trait, Type)` pair: look up `Trait` in the current module (shape 1 above), chain-follow its `ModuleEntry::Import` / `Reexport` binding back to its **defining module** (the module holding the canonical `ModuleEntry::Trait`), then probe that one module's symbol table for the synthetic key `impl$FQTypeName$FQTraitName`. Bounded by chain depth (typically ≤ 3), not by the import set, not by the universe. No closure walk; no cycle detection; per-symbol point-to-point only. The impl is reachable from N iff the trait is reachable from N — encoded structurally by the chain-follow terminating at the trait's home.
4. **Bulk introspection — current module only.** Functions like `all_type_defs`, `all_macros`, `known_type_names` iterate `ctx.current_symbol_table().iter()` only. Multi-module aggregation (REPL `/list`, `/imports` cross-module views) is composed at the **orchestrator (session / REPL) layer**, not inside a typecheck pass.

**Mutating writes** always go through `ctx.current_symbol_table_mut()`. Two write-target classes:

- **`ModuleEntry::TraitImpl` writes** target the **trait's defining module** (Decision 45 Pattern B). At the write site (Pass 1 stages a signature-only shell; Pass 2 stages the body-checked impl), the orchestrator selects the target staging table by chain-following the trait reference (shape 3, write-side) — identical to the read-side primitive. The result: the writer's module M is NOT mutated; the trait's home is.
- **All other writes** (non-impl entries: `TypeDef`, `Def`, `Constructor`, primitive registrations, type-name pre-seeds) target the **current synthetic / user module being bootstrapped or checked**. For synthetic-module registration (`register_primitives` etc.), `current_module` is the synthetic module name (`primitives`, `macros`) — the natural lexical scope; no chain-follow involved. For user-mode typecheck passes, `current_module` is the form's owning module.

## 2. Ordering within the slice

The slice has internal dependencies that bind the work order tightly. Per Decision 46, **Wave 3a-α (the §1.A locality refactor) lands before Wave 3a-β (the §1.B triad migration)**. Within each sub-wave the audit's remediation #1 is a load-bearing prerequisite for the facade migration; FIXME 0098 Phase 1 is a hard external prerequisite (lives in the types slice).

0. **Wave 3a-α — locality-correctness refactor (§1.A; α1–α16)**. Replace 40+ direct `self.modules.X` access sites with the four principled access-pattern shapes per Principle 17. Retarget the ~6 cross-module mutating writes to the trait's defining module per Decision 45 Pattern B (α15). Delete the first-pass `transitive_import_closure` function (α14) and the defensive synthetic `(import [macros [*]])` glob injection (α13). Convert synthetic-module type references to FQ-at-registration (α12). Add the `_in_module` / `_with_state` accessor-pair convention (α16). **α is a precondition for β**: without it, an orphaned `self.modules.X` pierce in a β-wave typecheck pass would read live during cluster mode (ignoring staging) and silently weaken Decision 44's cluster-atomic guarantee. α completes when no `self.modules.X` access remains outside the four shapes (Decision 46 acceptance criterion 1), `find_impl_for_type` uses chain-follow (criterion 3), bulk-introspection paths are current-module-only (criterion 4), and the existing test suite is green (criterion 5).

1. **External prerequisite — Wave 0 (NOT in this slice; lives in `cranelisp-types`; authored by /arch, not /design)**: per Phase 2 revision #2, /arch authors `ResolutionGap` (FIXME 0098 Phase 1) in `cranelisp-types` in Wave 0 before any consumer slice begins. **β-wave is blocked on Wave 0 for `ResolutionGap`** — rows 1, 4, 5, 13 all reference it. (`CheckError`, `CheckResult`, `ReplSnapshot` move OUT of `cranelisp-types` per FIXME 0100 Phase 1 — the typecheck slice owns those moves and they happen alongside row 1's pivot, not in Wave 0.)    - #2 (`finalize_impl_method` extraction) reduces the surface row 1's `&self` pivot must touch in `traits.rs`.

## 6.5. Anti-pattern guardrails — what MUST NOT appear in the α/β implementation

The /dev (typecheck) agent implementing α (and subsequently β) is bound by these explicit negative invariants. They are checked by `/review` typecheck audit + the structural unit tests in §5. Any post-α code with one of these shapes is a defect.

**Forbidden patterns.**

- **`transitive_import_closure(module) → Set<ModuleFullPath>`** (or any equivalent function with that shape — collecting the "set of all modules transitively reachable from M" with `HashSet visited` and per-edge bookkeeping over `imports` + per-symbol `Import`/`Reexport` entries). The α-first-pass introduced exactly this; the redo deletes it. The navigation primitive is per-symbol chain-follow along `source.module` — one edge at a time, per-name — not a graph-level enumeration.
- **"Walking the import graph"**, "graph traversal", "cycle detection", "visited set", "bounded by loaded module count". These are all rationalisations for the closure-walk pattern. Chain-follow terminates at a non-`Import`/non-`Reexport` entry by construction; no cycle defence is necessary. If a chain doesn't terminate, the upstream symbol-table state is malformed (a defect upstream — typecheck does not paper over it).
- **Writer's module as the impl storage location.** Pattern A is reversed (Decision 45 user-arbitration 2026-05-10). `ModuleEntry::TraitImpl` writes go to the **trait's defining module**, identified by chain-following the trait reference at write time. The writer's bounded context resolves the target table; it does not own the table.
- **Defensive synthetic glob imports**, e.g., `(import [macros [*]])` injection into `primitives.imports`. Synthetic modules have empty `imports` / `exports` `Vec`s by invariant (Principle 17). Cross-synthetic-module references are constructed FQ at registration time (`Type::ADT(macros_fqtn("SList"), …)`). The α-first-pass injected the glob as a workaround for the closure-walk path under Pattern A; the redo removes it.
- **"Universe scan" / "iterate all modules" / "scan reachable modules"** — any pattern that touches `self.modules.iter()`, `symbol_tables.iter()`, or similar enumeration outside the four principled shapes (Principle 17). Bulk introspection is current-module-only (shape 4); multi-module aggregation lives at the orchestrator (session/REPL) layer.
- **Short-name fallback chains** — patterns like "if absent from current module, try primitives", "if absent from primitives, try root", "if absent from root, scan loaded modules". Short-name resolution is current-module-only. Universally-feeling symbols arrive in the current module via implicit prelude injection (per-symbol `ModuleEntry::Import` bindings, spec §8.8.1) — the bindings carry the reach.
- **Auto-injecting primitives into user modules outside the implicit-prelude pathway.** The prelude injection (spec §8.8.1) is the single canonical pathway. No ad-hoc "and-also-try-primitives" fallback at name-resolution time.

**Chain-follow termination property** (informative, not a forbidden pattern — clarifying why no cycle detection is required). Chain-follow proceeds along `ModuleEntry::Import { source }` / `ModuleEntry::Reexport { source }` entries: each step replaces the current name+module with `source.symbol`+`source.module` and re-looks-up. The chain terminates when a non-`Import`/non-`Reexport` entry (the canonical definition: `Def`, `TypeDef`, `Trait`, `TraitImpl`, `Constructor`, `Macro`, `PlatformDecl`) is reached. The chain is finite by structure — each step strictly changes `(module, symbol)` to a new pair; if the upstream module's table has a canonical entry for `symbol`, the chain terminates there. If no canonical entry exists at any step, the chain terminates with `None` — the binding is dangling (a defect upstream in import-resolution; typecheck surfaces it as an `Err`, not as an infinite recursion). No `HashSet visited` is required; no "max depth" parameter is required.
