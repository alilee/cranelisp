# The §3.3 index cache-channel severance (§25.5 retirement) needs a /design-coordinated wave — deferred from the 0604 fix

`index-worker-isolation.md` §3.3 mandates severing the index feed's disk-cache
channel: delete `write_index_meta` (branch (c)'s benign `.meta` + source-hash +
`record_compiled`), and stop `try_branch_b`'s `record_source_hash` — retiring the
§25.5 index→import cache-hit. The 0604 `/dev` deployment implemented and then
**reverted** §3.3, landing only the in-memory isolation half (§3.1 docstrings +
§3.2 prelude-fallback snapshot). Two findings block a unilateral /dev severance.

## 1. §3.3 does not fix 0604 (the writer is FOREGROUND — proven)

The 0604 deterministic recipe is `--run --no-cache`. The index feed is **provably
inert** under it:

- `arm_importable_index()` is REPL-only (`main.rs:342`); `run_one_index_task`
  drains an empty worklist under `--run`. **Instrumentation: `index_one_module`
  fires 0× under `--run`, 39× under REPL.**
- `--no-cache` gates the cache channel independently (`write_index_meta` /
  `try_branch_b` recorder need `cache_dir = Some`).

So severing the cache channel cannot change the recipe's outcome — the residual
phantom writer re-scopes to the FOREGROUND concurrent-compile path (0604's S110
disposition; re-attribution owed to `/qa`). Severing §3.3 buys the coupling-class
closure the contract argues for, but not the 0604 fix.

## 2. §3.3 retires §25.5, which breaks three committed e2e pins

`agent.md §25.1/§25.5` is pinned by three GREEN tests in `tests/search.rs`:

- `search_branch_c_stale_meta_typechecks_writes_meta` — asserts branch (c) writes
  a `.meta`;
- `search_burndown_arms_at_repl_startup_neg_not_on_first_search` — asserts the
  startup burn-down produces the index `.meta`s;
- `search_index_to_import_is_meta_cache_hit` — asserts the §25.5 cache-hit.

Landing §3.3 turns all three RED (verified — they were the 3 regressions the §3.3
attempt introduced before revert). A /dev change-set must not redden the baseline.

## Ask (the coordination the retirement needs)

Retiring §25.5 is a design decision with cross-owner blast radius. If `/design`
(int) confirms the retirement (weighing that it does NOT fix 0604 and IS a bounded
perf regression — one re-typecheck of an actually-imported module), coordinate it
as ONE wave:

1. `/design` updates `agent.md §25` (retire §25.5) + `index-worker-isolation.md`
   §3.3 status;
2. `/qa` / `/testing` retire or invert the three `tests/search.rs` §25.5 pins (+
   any `search_index_rebuild_from_meta_reproduces_results` dependence);
3. `/dev` severs (`write_index_meta` delete + `try_branch_b` recorder removal) in
   the SAME wave, so the baseline stays green.

Alternatively, `/design` may keep §25.5 (the in-memory isolation §3.1/§3.2 already
closes the live-table coupling; the disk cache-hit is a genuine optimization whose
only 0604 relevance is refuted) and mark §3.3 WON'T-DO — in which case delete this
FIXME and annotate §3.3.
