# 0033 — Structural declarations live as fields on `SymbolTable`, not as a parallel `ModuleStructure`

`pipeline-v4.md` §9.1 places `imports: Vec<ImportSpec>`, `exports: Vec<ExportSpec>`, `platforms: Vec<PlatformSpec>`, and `submodules: Vec<ModDecl>` directly on `SymbolTable` (alongside `symbols`, `next_got_slot`, `got`). The `ModuleStructure` struct currently in `src/save.rs` (Sprint-57 transitional shape) dissolves: every field on `ModuleStructure` migrates 1:1 to a field on `SymbolTable`, the `SharedState.module_structures: DashMap<ModuleFullPath, ModuleStructure>` parallel store goes away, and `src/save.rs`'s regenerator reads structural metadata from the `SymbolTable` it already holds. The four field types reused are `cranelisp_types::ImportSpec` (already exists, line 369), `cranelisp_types::ExportSpec` (already exists, line 378), `cranelisp_types::PlatformSpec` (already exists, line 396), and `cranelisp_types::ModDecl` (already exists, line 405) — no new boundary types are introduced. Worker write-path (in `src/worker.rs` form-handlers): each `(import …)` / `(export …)` / `(platform …)` / `(mod …)` form processed during form-by-form classification appends to the relevant field on the symbol table for the form's owning module. Rejected alternatives: (a) keep `ModuleStructure` as a parallel store optimised for save-path access — the same DashMap-vs-entry divergence Decisions 25 and 26 reject (Principle 7 violation: the `(import …)` form's structural record lives in two stores that can drift); (b) put structural decls on a separate `SymbolTableMeta` companion struct keyed by module path — adds a third map without removing the duplication (`SymbolTable` and `SymbolTableMeta` would still need to be looked up together for save and cache); (c) reconstruct structural decls on save by iterating `ModuleEntry::Import` and `ModuleEntry::PlatformDecl` entries — loses the *original specification* (groupings, source ordering, `ImportNames::Glob` vs explicit name lists) that the spec requires for `.cl` regeneration §6.4; the per-symbol entries are the *resolved effects*, not the originals. Defined Sprint 58 Wave 1 alongside Step 5a. Canonical location: `crates/cranelisp-types/src/module.rs` `SymbolTable`. Owner: `/typecheck` for the field shape (it owns `cranelisp-types/src/module.rs`); `/int` for the writer placement in `src/worker.rs` and the reader migration in `src/save.rs`. Rationale: Principle 7 (single source of truth — structural decls live in one place) + Principle 11 (single store on `SymbolTable`, consistent with Decisions 25, 26) + Principle 1 (decoupling — `src/save.rs` reads from the same store as cache serialisation reads from, no third coordination point).
