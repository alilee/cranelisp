### Verdict: **SIGN-OFF** (no revisions, no blocks)

The hide-primitives story lands **entirely in `stdlib/`-owned files** (module structure + selective re-export + prelude composition). It requires **no compiler change, no `cranelisp-types` change, and no spec-semantics change** — the model it needs is already normative. No FIXME filed to `/spec` or any compiler skill on architectural grounds. The rest of the scope (docs, examples, demos, exemplar, qa repros) has no architectural surface and is signed off without comment.

### The crisp constraint for the hide-primitives design

> **"Hiding primitives" is a bare-name-curation concern only. It governs which names the prelude (and curated stdlib shell modules) re-export as bare names — nothing more. It MUST NOT touch reachability: the fully-qualified form `primitives/<name>` works regardless of imports and regardless of prelude content (spec §8.9.1, §8.11.4, §3.1), and that escape hatch is constitutionally guaranteed and MUST remain. An empty prelude stays valid; the core language — primitives, special forms, inference — keeps working with zero prelude content (spec §8.8.1). The prelude/stdlib never becomes load-bearing: nothing the curated surface re-exports may be *required* to compile a program that uses the FQ form.**

Restated as the safe/unsafe line `/stdlib` and `/spec` design within:

- **SAFE (this sprint's job):** Decline to re-export raw primitive names (`add-i64`, `vec-get`, …) as bare names through the prelude; instead re-export curated, Clojure-aligned names from stdlib shell modules (`num`, `text`, `seq`, …) that wrap or alias the primitives. The user sees `(+ a b)` / `(get v i)`, not `(primitives/add-i64 a b)`. This is exactly the `print`→`platform.stdio/print` re-export precedent (§8.4.7) and the `sconcat`-public-but-only-some-re-exported precedent (§9.1) applied to primitives.
- **UNSAFE (out of scope; would require spec/compiler work — DO NOT do here):** Making the FQ `primitives/<name>` path *unreachable* (a "private primitives module"), or making any curated wrapper the *only* way to reach a capability such that an empty-prelude / no-stdlib program can no longer express it. That inverts the optional-prelude and primitives-work-without-prelude principles and would be a spec-semantics change, not a curation pass. If `/stdlib` finds it *wants* an enforced-private primitives surface, that is a FIXME `target: /spec` + `/arch` for a future sprint — **not** in S86 scope.

### Why this needs zero compiler/spec work (the three assessed points)

1. **Tension with the principles — resolved by the curation/reachability split.** Spec §8.9.1 already states primitives "are stored in **qualified form only** … NOT available as bare names unless brought into scope through (1) the implicit prelude … or (2) an explicit import," while "fully-qualified references … work **regardless of imports**." So primitives are *already hidden at the bare-name layer by construction* — the prelude is the only thing that surfaces them as bare names today. "Hiding" is therefore not a new capability; it is **choosing what the prelude re-exports**, which is already `/stdlib`'s prerogative. The optional-prelude principle (§8.8.1: "An empty prelude is valid. The core language … works without any prelude content") and the FQ-always-reachable guarantee (§8.9.1, §8.11.4) are the two invariants that keep the curation safe; both are pre-existing normative text. No principle is strained; no new principle needed.

2. **Interaction with Decision 0048 + the §8.6.x visibility model — none required.** Decision 0048 makes primitives "functionally equivalent to any other module" from session-init onward (`PRIMITIVES_TABLE` + GOT-indirect dispatch). That is precisely what makes the curation a pure stdlib concern: because `primitives` is an ordinary module, the existing per-symbol `Import`/`Reexport` machinery (§8.4 export, §8.6.2 chain-follow, §8.4.7 re-export provenance) is *already sufficient* to wrap/alias/re-export any primitive through a curated stdlib module. The hide-primitives surface is built with the same `(export …)` / `(import …)` tools the stdlib already uses for `Option`/`Result`. **No visibility-semantics change** (no new `pub(crate)`-analog for `.cl` modules, no "private module" construct) is needed — and inventing one would be the unsafe path above. Confirmed: the story lands purely in `stdlib/`-owned `.cl` files.

3. **`cranelisp-types` / cross-crate interface impact — none.** Confirmed across the whole sprint. No boundary DTO, trait, or facade changes. The self-testing requirement reuses already-landed surface: `discover-tests` (`DefKind::PrimitiveExtern`, returns fn-value pairs) + `catch-runtime-error` (the 0273 in-language runner, S81) + `stdlib/testing/` helpers — all in place; no new cross-crate type. Note the existing **fork-join error-slot ferry obligation** recorded against `test-discovery.md` (a pre-existing §12.4.3 defect, worker-side panic swallowed): if stdlib self-tests exercise `catch-runtime-error` *around parallel branches*, they may surface it — that is a **defect-capture** event (→ `/qa` narrow repro per the user-proxy protocol), **not** an S86 architectural blocker. Flagged so `/stdlib`+`/qa` recognize it if it appears.

4. **Interim-architecture risk (Principle 8) — none.** Nothing in scope builds a throwaway intermediate. The hide-primitives surface is curation over a settled mechanism (Decision 0048 is landed; the visibility model is settled); the curated shell is the target shape, not a stepping stone. The legacy-demo disposition is explicitly *archive-and-keep-running* (not delete, not stub) — the opposite of an interim implementation; it is a regression-guard retention decision with no architectural exposure. Plan §1.3 ("Design the end state first … no interim versions") already binds `/stdlib` to the non-interim discipline.
