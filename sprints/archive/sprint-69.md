**Status**: PHASE 3 — 8 audits RE-AUTHORED 2026-05-19 with configuration-aware discipline (memory: `feedback_audit_per_item_analysis.md` updated to require reading architectural configuration BEFORE disposition). **Goal**: Hammer the facade in at the crate edges. The three mechanical conformance tests go green AND each crate gets a close-reading audit (lib.rs + facade + public-api.txt read as a triple) that catches the drift the tests can't see. Every drift surfaced — by either path — is reconciled, either source moves to match the facade (the default) or the facade moves to match source (extraordinary, gated by /arch + user signoff). Audit memos commit as durable per-crate artefacts so future sprints can re-run the same review and diff.

## Scope

### Definition of done — three structural-conformance tests green AND per-crate audit clean

The mechanical conformance tests are necessary but not sufficient. Each enforces a narrow slice:

| Test | What it actually proves | What it cannot catch |
|---|---|---|
| `facade_compliance.rs` (text-grep) | Every pub-api leaf-name appears as a substring somewhere in the facade .md | Shape drift (facade says `enum`, source says `struct`); items mentioned only in cross-refs or "Forbidden patterns" sections; missing contract detail (variant sets, field types, method signatures) |
| `facade_pif_rows.rs` (17 targeted tests) | The specific shape of ~17 items from S67's disposition table | Anything outside those 17 rows — the long tail of pub-api items |
| `public_api_relocations.rs` (cargo public-api diff) | Pub-api hasn't drifted from the committed baseline | Whether the baseline itself matches facade intent |

The sprint adds a **fourth gate**: per-crate close-reading audit memos. The mechanical tests catch regression; the audit memos catch the qualitative correctness the tests don't enforce. Sprint closes only when both gates are clean.

The user-named definition: **`cargo public-api` output matches the documented facades and sequences**. Three mechanical tests + 8 audit memos embody that contract:

| Test | What it asserts | Today |
|---|---|---|
| `tests/facade_compliance.rs::facade_compliance_orphans_match_expected_sprint_67_baseline` | Every named pub item in each baseline appears in the corresponding facade doc | 3 backend orphans (ALIGN / Output / Owned) |

Sprint closes when all three are green. **Exception path**: if any row cannot be reconciled by moving source without breaking a load-bearing invariant, `/arch` is invoked to amend the facade (and Decision register as needed) — that's the "extraordinary" branch the user named. Default is source moves; facade moves is by exception.

### In-scope work — categorized

**Category 0 — per-crate close-reading audit (Wave 1, parallel × 8)**

One /design agent per crate. Inputs: `crates/{crate}/src/lib.rs` (declared pub surface), `design/arch/facades/{crate}.md` (binding contract), `crates/{crate}/public-api.txt` (live boundary). Read together. Output: `design/arch/facades/{crate}-audit-s69.md` naming four classes of finding:

Each finding is filed as either (a) source-side work folded into Wave 3, (b) facade-doc work folded into Wave 2, or (c) deferred-with-rationale (becomes a FIXME against the owning crate's /design for next sprint). ### Per-question answer

**Q1 — Row 27: intrinsics → primitives physical move acyclic?**

The move is **already complete in source**. `crates/cranelisp-primitives/src/string.rs` and `vec.rs` exist with the 15 `str_*` extern fns and `vec_len` as `pub(crate) extern "C" fn` carrying `#[unsafe(export_name = "…")]`. `crates/cranelisp-intrinsics/public-api.txt` contains zero `cranelisp_intrinsics::string::str_*` or `cranelisp_intrinsics::vec::vec_len` lines. Workspace dep direction is `cranelisp-primitives → cranelisp-intrinsics` (allocator dependency for `int-to-string` etc.) which is acyclic; the reverse edge does not exist.

What is **not** done: (a) `facades/intrinsics.md` §"String primitives" still describes the str_* family as physically-here-pending-FIXME-0180 — this is the documented drift in FIXME 0213 (Category C). (b) `facades/primitives.md` §"Consumed surface" claims "Primitives does NOT depend on `cranelisp-intrinsics`" but `crates/cranelisp-primitives/Cargo.toml` lists `cranelisp-intrinsics = { path = "../cranelisp-intrinsics" }`. This contradiction is a facade-doc bug, NOT a structural issue — the dep is correct (primitives' `int-to-string` etc. need the allocator) and acyclic. (c) the PIF test `row_27_*` asserts `str_helpers_in_primitives > 0` by greppling for `pub ... str_concat` in the primitives public-api.txt — but per Decision 0048 those are `pub(crate)` and correctly do not appear in pub-api. **The test as written is inconsistent with Decision 0048 and would never pass against the target shape.**

**Resolution**: Row 27 reclassifies from Category A to **Category B (test assertion fix) + Category C (facade-doc fix)**. The Wave 3 atomic `/dev (intrinsics + primitives)` brief deletes from the sprint — no source move is required. The Wave 1 audit briefs for primitives + intrinsics must surface the Cargo.toml↔facade contradiction (currently undocumented in facades/primitives.md §"Consumed surface"). The /qa test refinement extends to include row_27 — assert intrinsics-side zero (already true) AND assert primitives-side presence via the GOT-uniform `PRIMITIVES_TABLE` static line (which IS in pub-api) or via source-tree presence of `string.rs`/`vec.rs`, NOT via `pub` extern-fn enumeration.

**Q2 — Row 21: TypeCheckEnv narrowing changes the cluster-atomic protocol shape recorded in Decision 44?**

No. Decision 44 (third amendment, 2026-05-13) names `check_forms(parsed, ctx, symbol_tables) -> Result<(), CheckError>` as the canonical single-call facade and `ClusterContext::current_symbol_table[_mut]()` as the single accessor through which 91 register-call sites flow. `TypeCheckEnv`'s public surface is **orthogonal** to the cluster-atomic protocol — it carries typecheck-internal state (`next_type_id`, generalisation context, deferred resolutions) that the orchestrator does not touch. The facade target is `new` + `next_type_id` (FIXME 0172's residue from S67 W3). The 17 methods currently `pub` are cross-crate `int` consumers documented in FIXME 0187. Narrowing them to `pub(crate)` is mechanical follow-up after `int` consumers migrate (FIXME 0187's Phase A) — the migration path is `SymbolTable::get` reads with per-symbol chain-follow per Principle 17, NOT a new orchestrator protocol.

Risk surface: if Wave 3 /dev (typecheck) narrows the methods before Wave 3 /dev (int) lands FIXME 0187's consumer migration, the `int` build breaks. **Sequencing inside Wave 3 must be int-first-then-typecheck**, or both crates land in one atomic /dev (typecheck + int) brief. Recommend the atomic-brief shape; the work is structurally similar to S68 Wave 4's primitives + backend + src/ flip.

**Q3 — rev3 (`describe_symbol` routing): requires a SharedState facade change?**

Self-contained to `int`. The facade question is whether `describe_symbol` on `CompilerSession` correctly routes through `shared.symbol_tables` for the synthetic `primitives` module. Per Decision 0048 + the post-S68 invariant ("primitives dispatch is functionally equivalent to any other module"), session-init Arc-clones `PRIMITIVES_TABLE` into `session.symbol_tables` at `ModuleFullPath::primitives()`. From that point any `describe_symbol`-family lookup keyed on `primitives/add-i64` should find the `ModuleEntry::Def` and format its scheme + classification through the standard universal-display path. The 30s timeout suggests either (a) the lookup hangs on a wait-for-ready condition specific to the primitives entries (e.g., a worker-publish flag that primitives entries don't carry because their lifecycle is `Code::Primitive`) or (b) describe_symbol's routing falls through to a slow path that REPL-evals to a fully-compiled symbol that doesn't exist for the marker variant. Both are int-internal — no `SharedState` shape change, no new facade surface. The fix likely touches `src/repl.rs` or `src/session_v4.rs` to handle the `Code::Primitive` case identically to `Code::Jit`/`Code::Linker` for the read path.

Risk surface: cross-skill minimal-repro discipline applies. The 30s timeout could mask a deeper interaction between `Code::Primitive` lifecycle and a wait-loop in `int`'s readiness machinery. Wave 1 int audit and Wave 3 /dev (int) brief should both call this out as a candidate for early reduction via `/info` slash command tracing.
