# 0039 — Per-defn source lives on `Introspection.source`; `SymbolTable.defn_order: Vec<Symbol>` preserves canonical ordering for regeneration; errors carry `ErrorLocation` (coordinates as data, formatting downstream).

Source text for each defined symbol is stored on `Introspection.source: Option<String>` per Decision 38 — there is no module-global source store. For file-based modules, the parser holds the file `Arc<str>` transiently, slices each defn's source `file[defn.span.start..defn.span.end]` into a per-defn snippet on `Introspection.source` (when introspection is enabled), then drops the file string. For REPL evals, `Introspection.source` is the eval text directly. `Defn.span` is per-defn-local (offsets into the snippet) for post-parse usage; parse-time it's file-global until the file string is partitioned.

**`SymbolTable.defn_order: Vec<Symbol>`** — a new field on `SymbolTable` that records the canonical defn ordering for `regenerate_backing_file`. Appended at first registration of each symbol; redefinition does NOT reorder (redefinition replaces in place, preserving the symbol's original position). Phase 0 (parse-time) seeds it from the parser's declaration-order list of defn names; REPL eval appends one entry per new defn via `SymbolTable::append_defn_order(&mut self, sym)` (a brief per-eval `&mut SymbolTable` window, the same shape as Phase 0's structural-decls write). `regenerate_backing_file` walks `defn_order`, looks up `introspection[fq].source` for each, concatenates, writes to the .cl file.

**Errors carry `ErrorLocation`.** Per `facades/types.md` §"Errors and warnings" — every `CranelispError` variant that points into source carries an `ErrorLocation { span, file, fq, line_col, context }`. `span` is always populated; `file` is populated when known (file-based modules); `fq` is populated for post-parse errors (links the error to its defn for introspection-based source resolution); `line_col` is populated when source is in hand at error-construction time (cheap to compute); `context` is populated when the producer wants inline source snippet (parse errors always; typecheck/codegen errors typically defer to the formatter's introspection lookup). The integration-layer formatter (`Sess::format_error`) selects display strategy based on what's populated: REPL/trace mode uses `fq` to resolve `shared.introspection[fq].source` for rich inline display; production batch shows `file:line:col: error: message` plus any `context` snippet. `Warning` carries the same `ErrorLocation` shape for uniform formatting.

**Why per-defn source on Introspection wins.** (1) REPL evals have no coherent "module file" — the user creates defns interactively; per-defn source is the natural unit. (2) Mode discrimination becomes uniform — `shared.introspection.is_some()` governs whether ANY per-symbol metadata (including source) is retained; production batch carries zero source overhead. (3) File-based modules don't lose anything — the parser partitions per-defn snippets at parse-time; the file `Arc<str>` is transient. (4) `regenerate_backing_file` becomes a clean iteration over `defn_order` + `introspection.source`. (5) Eliminates a SharedState field — there is no `module_sources` map.

**Parse errors are self-contained.** The parser holds the file `Arc<str>` at error-construction time and populates `ErrorLocation.context` with surrounding lines before the file string drops. After parse completes successfully, the file string drops; parse errors that already occurred carry their own context.

**Typecheck/codegen errors resolve via introspection at display time.** These producers populate `fq` + `line_col`; the formatter looks up `shared.introspection[fq].source` (when introspection is enabled) for rich snippets. Production mode (introspection = `None`) shows `file:line:col` only — acceptable degradation since the user can open the file and look.

Rejected alternatives: (a) keep `module_sources: DashMap<ModuleFullPath, Arc<str>>` on SharedState — duplicates retention (file string + per-defn snippets); REPL persistence semantics get awkward (file grows with redefinition history); doesn't unify mode discrimination; (b) per-defn source on `ModuleEntry::Def` directly — same `ModuleEntry::Def` bloat issue Decision 38 rejects for other introspection fields; (c) errors carry only `Span` and rely on a separate display-layer source lookup — works but loses self-containment of parse errors (which need source context that may not be retained), and forces every formatter to know about `shared.introspection` access patterns; (d) errors carry the full source snippet inline always — duplicates information when introspection is enabled (snippet is already resolvable via `fq`).

Canonical locations: `facades/types.md` (`ErrorLocation`, `LineCol`, `LineColRange`, `SymbolTable.defn_order`, error variant reshape, `Warning` reshape); `facades/int.md` (`Sess::symbol_source(fq)` accessor; `regenerate_backing_file` body); `Introspection.source: Option<String>` is on `SharedState.introspection` per Decision 38.
