# Sprint 100: Ownership inference — the memory-model design phase

**Status**: CLOSED (user approval 2026-07-03) — design deliverable set complete; exit gate PASS-with-notes (`/arch`, 2026-07-03, spine §12); ROADMAP re-sequenced (Phase-H delivery sequence: S101 R3 machinery → increment I → increment II → `--release`)

> **R3 resolved (user direction, 2026-07-02).** Reject the ABI-pinning dodge (candidate i). The REPL/dev-session **re-typechecks and recompiles caller functions on redefinition**, managing the cascading type/mode errors that follow — building the dependent-recompilation machinery the session currently lacks (redefinition is a GOT-patch only today). This is *forced* by access-pattern-as-ABI: a redefinition that changes a param's inferred mode invalidates every caller's emitted inc/dec schedule, so callers must be re-inferred + recompiled, and cascades (a caller that no longer typechecks under the new signature/mode) surfaced gracefully. The arch spine designs this; it supersedes R3's candidate-(i) in the Phase-2 review. Relevant precedent to build on: `ModuleDependencyGraph` transitive-dependents + `recompile_module_and_dependents` (S35/S37), the error-cascade machinery (S45 `reset_module`/embedded-original-error), `session_v4.rs` redefinition path.

**Goal**: Design an **interprocedural ownership-inference architecture** — computed at typecheck, consumed by the backend, requiring **no user annotation** — that drives parallel-memory contention toward zero (unnoticeable small-case overhead; strong parallelisation dividends at scale), so `--release` can later be built against a settled memory model. This sprint produces the **design** (arch spine + per-crate proposals + verification plan + staged implementation roadmap), not the implementation.

## Why this sprint, why now — the Phase-H opening, redirected

The ROADMAP has Phase H opening at S100 with the **`--release` efficiency tier**. **This sprint re-sequences that opening.** S99 closed with a *measured* result: the parallel-search slowdown is essentially all **contention**, dominated on the release backend by **(b) atomic-RC cache-line bouncing**, whose driver is **vec-COW leaf-refcount volume** (81 `rc_inc` + 2 allocs per shared 81-cell copy; ~170M `rc_inc` across 2.1M copies). No pre-Phase-H substrate lever restored the floor; a release backend alone does not fix it; and **(a) allocator + (b) RC contention couple** — the cure must be co-designed.

User direction (2026-07-02, design conversation): **we do not build `--release` until the parallelism/memory-contention problem is solved.** The roadmap pencilled the cure as "Perceus / mutate-in-place / non-atomic thread-local RC" — one paper choice. This sprint runs the deep design phase that explores the real space and converges. It converged, in-conversation, on a **leading-candidate architecture** (below). This is the first Phase-H sprint — just the memory-model design, not `--release`.

## The performance north-star (acceptance frame for every mechanism)

Both required; a mechanism that wins one by sacrificing the other does not qualify:

1. **Unnoticeable small-case overhead.** The common single-threaded / small-data path must not perceptibly regress. Pay-for-what-you-use — machinery invisible until the workload is large enough to profit.
2. **Strong parallelisation dividends at scale.** Copy-a-`Vec`-of-shared-heap-ADTs-under-speculative-parallelism runs at a *slight per-core discount to serial*, not the 2–15× *penalty* measured today.

Carried constraints (binding): **keep nested ADTs** (no `0416` bitmask dodge); **substrate/stdlib/compiler, not exemplar hand-tuning**; **co-design storage+RC** (S99 coupling finding).

## The leading-candidate architecture (settled in the Phase-1 design conversation)

**Interprocedural ownership inference at typecheck, consumed by the backend, no annotations.** The insight that makes it work: doing the analysis over the **resolved call graph at typecheck** (not backend-locally) gives the interprocedural propagation escape analysis lacks — the fact "`xs` is borrowed" rides through every caller *by inference*, fixing escape analysis's can't-see-through-a-call limit **without** the annotation burden of declared ownership types. Precedents for "never annotate": **Roc** (RC + inferred reuse, zero ownership annotations), **MLKit** region inference, **GHC** demand/cardinality analysis (per-function inferred usage signatures).

**The unifying frame — one analysis, several queries, several codegen mechanisms.** "Escape analysis", "ownership inference", and "RC" are not separate subsystems; they are different *queries* against one shared lifetime/flow analysis, each driving a distinct backend mechanism:

| Query the analysis answers | Output | Backend mechanism it drives |
|---|---|---|
| Is this param only **read**? | Borrowed vs Owned | pointer-pass; elide `inc`/`dec` |
| Does the value **escape its frame**? | frame-escapes / not | **stack/region** alloc vs heap |
| Does the value **cross a thread**? | confined / not | **non-atomic** vs atomic RC |
| Is the value **uniquely owned** here? | Unique / Shared | **in-place reuse / mutable borrow** vs clone |
| How is this type **duplicated**? | Copy / RC / deep-clone | bit-copy / `rc_inc` / structural copy |

So the **typecheck deliverable is one flow-analysis pass with multiple outputs**; the **backend deliverable is a set of codegen mechanisms each consuming one output**. The `Copy`/`Clone` vocabulary names the per-type *duplication strategy* the analysis dispatches on (`Copy` = bit-copy/rc-free; cheap `Clone` = `rc_inc`/share; deep `Clone` = structural copy for owned-write-while-shared; **reuse** = in-place for owned-write-while-**unique**). `Copy`-ness is structurally derivable (Copy iff all fields Copy); surfacing `Copy`/`clone` as *stdlib vocabulary* is optional polish, not required by the mechanism.

**Where it bites S99:** the 81 per-copy `rc_inc` come from projecting Cells out of the Vec — **borrow-through-projection** (`(get xs i)` on a borrowed `xs` yields a *borrowed* element) makes all read access rc-free, shrinking the problem to genuine materializations; each materialization is then served by **reuse** (unique) or **clone / persistent-delta** (shared).

**Why Cranelisp is unusually friendly:** **monomorphization** makes per-instantiation mode inference concrete, largely dissolving the mode-polymorphism machinery (`Fn`/`FnMut`/`FnOnce`, multiplicity polymorphism) that makes inferred ownership heavy elsewhere. The AST already carries `resolved_call` + `inferred_type` (S55), so the call-graph + heap/Copy substrate exists. The design **refines Decision 24** (uniform-consume → per-param mode) and **subsumes** `borrowed_vars`/capture-by-borrow as principled output of one analysis (dissolving the ad-hoc S99 caveat into a general case).

**G3 preserved:** the mechanism is inferred and invisible; a "mutable borrow" is a physical-cell write permission that is sound *because* exclusivity guarantees no observer witnesses the mutation — observationally still immutable. No user-facing semantics change.

### 1. The typecheck→backend boundary-contract inversion — RULED: WARRANTED

The scope proposes computing ownership/mode inference at typecheck (interprocedural, over the resolved call graph) and passing per-param mode + per-site escape/confinement/uniqueness facts down on the `MonoExpr`/signature boundary — deliberately inverting `release-llvm-backend.md` §8.3's default ("derive borrow/own in-backend"). **I rule the inversion warranted**, on four grounds:

1. **§8.3's own contingency has fired, with measurement.** D-Rel-5 declined the facade field *"unless in-backend derivation can't reach the precision FIXME 0408 needs."* S99 measured exactly that ceiling: the dominant contention term (vec-COW leaf-refcount volume, ~170M atomic bumps) is attackable only with facts a local use-structure walk cannot see — that a param is borrowed *in the callee given every caller*, that a materialization is unique *given the whole call path*. In-backend derivation is local; locality is precisely the limit S99 proved we must escape. This is not a reversal of the release doc's judgment — it is the release doc's named escape hatch, taken on evidence (Principle 21 honored: measure before mechanism).
2. **The call graph lives in typecheck.** Monomorphisation (`traits/monomorphise.rs`) and `resolved_call` annotation are typecheck-owned; an interprocedural fixpoint belongs in the crate that owns the graph it walks (Principle 3 — the facts flow from where they are stable). Re-deriving graph knowledge inside the backend would duplicate it (Principle 7).
3. **Two consumers, one source.** Both tiers (Cranelift now, LLVM later) consume the same facts. In-backend derivation would either run twice (once per lowering path) or become a shared backend-internal analysis both paths depend on — a worse coupling than one inference feeding the existing shared input (`MonoExpr`, the release doc's own "two tiers, one input" §2/§3 framing — the input gets richer, the framing survives).
4. **Precedent alignment.** GHC demand/cardinality signatures, MLKit region inference, Roc — inferred usage/ownership is inference-domain output consumed by codegen, everywhere this has been built without annotations.

**Pinned consequences (binding on the Phase-3 contract):**

- **(a) Two classes of boundary fact — do not conflate them.** *ABI-bearing:* the **per-param mode vector on callable signatures** (rides `MonoDefn` + the callable's symbol-table entry, persisted in `.meta.json`). Caller and callee MUST agree — a callee compiled Borrowed (no dec) called by a caller emitting the consuming inc leaks; the reverse double-frees. *Advisory:* **per-site facts** (escape, confinement, uniqueness on allocation/capture/binding nodes). These are may-optimize permissions — a backend that ignores them is still correct, only slower. The contract document must state this monotone-soundness property explicitly; it is what keeps the conservative lowering available as the differential-testing oracle and makes increment staging safe.
- **(b) The absent-summary default IS Decision 24.** The lattice's conservative point (`Owned`/consume on every param) is byte-for-byte today's uniform consuming convention. No summary ⇒ Decision-24 behavior. This makes the contract backward-compatible with every existing cache, every unresolved edge, and every HOF call site — the refinement of Decision 24 is *strictly additive*.
- **(c) The facade breach is real, governed, and acceptable.** `cranelisp-types` (`mono_expr.rs` + the symbol-table entry) gains fields; D-Rel-5's "`MonoExpr` frozen w.r.t. the efficiency tier" is superseded for these fields and D-Rel-4's declined alternative is un-declined. This is acceptable because the breach lands at the **designed home for cross-crate facts** (the types crate, `/arch`-authored) — the encapsulation §7 protects is *codegen mechanism*, and every mechanism (parts 12–16) remains fully backend-encapsulated. The line moves from "all memory analysis in backend" to "**interprocedural facts above the boundary; intraprocedural analyses and all mechanisms below it**".
- **(d) The counterweight (Principle 2 — keep the interface narrow).** `compute_last_uses`, `HeapCategory::classify`, and every intra-function site decision **stay in the backend**. The boundary carries only what locality cannot compute. Phase 3 must resist enriching the contract with anything the backend can derive soundly in-function.
- **(e) Release-doc cascade.** §8.3/D-Rel-4/D-Rel-5 are amended by this ruling. A dated note box is added to `release-llvm-backend.md` §8.3 now (recorded below); the full §7-table/§13 rewrite is Phase-3 work alongside the master doc.

### 2. One analysis, several queries, several mechanisms — SOUND, with two sharpenings

The decomposition is the right frame: the five queries are projections of one flow/lifetime analysis, each driving a distinct mechanism, and framing them as one deliverable prevents three half-overlapping subsystems (the pre-S100 state: `borrowed_vars`, capture-by-borrow, Vec-COW last-use — three ad-hoc instances of the same missing analysis). It also honors Principle 21: the table IS the actors-and-functions map, drawn before mechanism. Two sharpenings:

- **The first-order pin (→ R2).** "Monomorphization dissolves mode-polymorphism" is true **for the statically-resolved call graph** (`resolved_call = Some`) — which is where the S99 prize lives (direct recursive calls, vec-COW in leaves). It is NOT true for closure-valued/higher-order call sites: a closure called through its code pointer exposes only its *type*, and putting modes on arrow types is exactly the `Fn`/`FnMut`/multiplicity machinery the scope rightly declines. The design must state the HOF fallback explicitly: **per-param modes attach to statically-resolved calls only; closure-typed call sites keep the uniform Decision-24 convention** (sound by (1b) above).
- **The `Copy` row currently has no mechanism (→ R5).** For an ADT that stays heap-allocated, "bit-copy" is vacuous — copying the pointer still needs the rc_inc. The `Copy` query only pays when the *representation* is a value (unboxed/inline — the S83 §12.1 per-type-representation relaxation). For the S99 `Cell` shape this is plausibly the single largest lever (an 81-slot Vec of value-`Cell`s copies with `memcpy` and **zero** RC ops — the whole 170M term vanishes). Parts 12–16 do not name it. Phase 3 must either add **value-representation flattening of Copy-eligible ADTs** as a named backend design question (with its ABI/`HeapCategory` consequences) or explicitly scope the `Copy` row to already-scalar types with rationale. Do not leave the row load-bearing-but-mechanismless.

No query is conflated; escape (frame) vs confinement (thread) are correctly distinct axes driving distinct mechanisms.

### 3. Monomorphization interaction + pipeline placement — RULED

**Where the analysis runs:** inside typecheck, **after** monomorphisation instantiation, over the mono call graph — per module-cluster with **imported summaries as boundary conditions** (Principle 17 module locality; the MLKit/GHC per-module-with-persisted-signatures shape). Fixpoint within a cluster for recursion; conservative default (Decision-24 point) at every unresolved edge (HOF sites, missing summaries). Outputs ride `MonoDefn`/`MonoExpr` + the symbol-table summary. This matches the crate facts verified above; no pipeline re-sequencing is needed.

**The "borrow monomorphisation" chicken-and-egg — resolved for increment I, kept open-by-design for II:** mode does **NOT** enter the mono key in increment I. One summary per instantiation, joined over call sites; a caller whose argument is more-owned than the callee's summary requires adapts caller-side (keeps ownership, decs later — sound and near-optimal). Mode-in-key specialization is a precision/code-bloat tradeoff that part 11 explores with data for increment II; the contract must not preclude it — which the scope's "design `Unique` into the lattice from day one" already provides.

**One correction to the scope's framing (→ R4):** monomorphisation dissolves borrow-vs-owned polymorphism; it does **not** dissolve *uniqueness*, which is a call-site-**dynamic** property (rc==1 at this moment), not a type-instantiation property. Static uniqueness proofs will cover a subset; the general increment-II discriminator is the **dynamic rc==1 check** (Perceus reuse tokens / drop-guided reuse — exactly how Koka and Roc do it, and exactly what today's Vec-COW mutate-in-place already does). The contract must accommodate the dynamic check as a first-class outcome, not treat it as a failure of inference. This also defuses most of the mode-in-key pressure: the reuse decision can stay dynamic per-site rather than forcing body duplication.

### 4. Two-increment staging — the right Principle-8 shape

Increment I (Borrowed/Owned + escape/confinement; borrow-elision, stack/region, RC modulation) is subsumed-not-discarded by increment II (uniqueness → mutable borrow → reuse) and by `--release`: I's outputs remain consumed unchanged; II adds queries and mechanisms without reshaping I's. Designing `Unique` into the lattice/contract day-one while implementing borrow-only first is exactly the "will this survive into the ring where the real mechanism arrives?" test passing by construction — the contract type never migrates, only the emitted precision grows. The (1b) absent-summary-⇒-Decision-24 default extends the same property downward: increment I is itself a refinement of the as-built convention, not a parallel one. **Confirmed.** One guardrail: increment I must not ship any borrow ABI that II's reuse tokens would break — reuse/drop-guided machinery is intra-function (Perceus-style), so this holds as long as part 16 keeps tokens off the call ABI; state that constraint in the contract.

### 5. Mode summaries + module caching (part 4) — coherent for batch; ONE genuine hazard at the REPL (→ R3)

`.meta.json` is a serialised `SymbolTable`; per-function mode summaries riding the callable's entry is shape-consistent with the existing design (Decision 33 family — one persisted shape, no side-table). **Batch/cache invalidation is already covered conservatively:** the manifest invalidates an importer when any direct import's *source hash* changes (`module-caching.md` §3), which over-approximates "callee summary changed". No new invalidation key is needed for `--run`/`--link`. Schema: summaries join the `schema_version`-gated payload — a version bump invalidates old caches cleanly.

**The hazard is REPL hot-redefinition.** Per-param mode is ABI (1a), and redefinition today patches the GOT slot **without recompiling callers** (verified: no dependent-recompilation machinery exists). A redefinition that changes a param's inferred mode would break every already-compiled caller through the patched slot — leak or double-free. Phase 3 MUST resolve this fork explicitly; the candidate resolutions, in rough preference order: **(i)** the JIT/dev-session tier pins the per-param *call ABI* to the Decision-24 default (callers always emit the consuming inc; callees always dec) and consumes only the advisory facts (borrow-through-projection, reuse, confinement, stack/region — which is where most of the S99 win lives anyway), reserving the full per-param-mode ABI for closed-world compilation (`--run` whole-program, `--link`, `--release`); **(ii)** mode joins the signature for redefinition purposes and a mode-changing redefinition triggers dependent recompilation (new machinery); **(iii)** something sharper Phase 3 finds. What is NOT acceptable is a contract that leaves the fork implicit — this is the DEF-6 class (invisible below a threshold, catastrophic above it).

### 6. G3 / semantics boundary — SOUND; no `/spec` engagement required

The "mutable borrow" claim holds: an in-place write on a value with proven/checked exclusivity is unobservable — no live reference can witness the mutation, so observational immutability is preserved. Decisive in-tree precedent: **Vec COW mutate-in-place already does exactly this today** (rc==1 + last-use ⇒ in-place write) and is spec-clean; increment II generalizes an existing, settled behavior rather than introducing a new semantic category. One caveat to carry into the design: the argument requires the language to expose **no reference-identity observer** (no pointer-eq, no address in `trace` output) — true today; the arch doc should state it as a standing precondition so a future introspection feature doesn't silently break the soundness argument. Gate-2's below-the-line ruling is confirmed: `/spec` engages only if `Copy`/`clone` stdlib vocabulary is surfaced (default internal-only is right — the mechanism never needs it).

### 7. Subsumption + composition claims — verified, with one pin each

- **Capture-by-borrow subsumption (ring2-rc §5.5.2): COHERENT, via the escape query — not via a wider borrow.** The general analysis subsumes the S99 structural-join rule as a special case of "capture only-read + parent provably outlives ⇒ Borrowed". The **ParBind-across-suspension caveat is discharged by classification, not permission**: a capture that flows into a trampoline-deferred continuation (returned IO tree, `LaunchContinue`, any suspension crossing) **escapes its frame** — the escape query returns "escapes", the retain stays. The lattice's escape axis MUST model suspension points as escape edges (the S98-0486 lifetime-across-suspension class) — this is a required element of parts 1–2, and part 17 keeps the ASan/UAF guard on exactly that site (→ R6). With that pin, the ad-hoc §5.5.2 caveat genuinely dissolves into the general case.
- **Lenient-eval / `0459` gate: composed, not competing — no hidden dependency.** The gate is scheduling; the analysis is memory. The gate's missing allocation/RC-density axis (`effect-concurrency.md` §3.1 static layer) becomes *derivable from* the analysis outputs (a branch whose materializations are borrow/reuse-served is cheap ⇒ admit). `0459` stays deferred-Phase-H with this design as its input; nothing here pulls it forward or blocks on it.
- **Persistent data structures (Axis 2): correctly composed — but keep the acceptance math honest (→ R8).** Spine-borrow + unique-delta-in-place (inferred transients) is the right composition and belongs in the arch doc as the shared-case materialization target. However persistent structures are a separate representation/stdlib axis NOT scheduled by increments I/II — so part 18's F1–F4 target numbers must be stated **per increment** (I alone; I+II; composed end-state with persistent DS / Copy-flattening), or the staged increments will be graded against a bar only the composed end-state can meet.
