# 0032 — `CodeStore` and `LinkerStore` are empty marker traits in `cranelisp-types` (with `Clone` super-bound)

The `C: CodeStore` parameter on `SymbolTable<C, L>` and `ModuleEntry<C>` is a *generic boundary*, not a method-bearing trait. The trait is defined as `pub trait CodeStore: Send + Sync + Clone + 'static {}` (with a blanket `impl<T: Send + Sync + Clone + 'static> CodeStore for T {}`) and `pub trait LinkerStore: Send + Sync + Clone + 'static {}` (same shape). Both default to `()` so that crates that do not handle compiled code (`cranelisp-typecheck`, `cranelisp-frontend`, the bulk of `cranelisp-backend` that operates on the typecheck-product symbol table) work with `SymbolTable` (i.e. `SymbolTable<(), ()>`) and never see the parameters in their signatures. The integration layer chooses the concrete `C = Code` (the `src/code.rs` enum per Decision 35, carrying `Arc<cranelisp_backend::jit::Jit>` for fresh-build and `Arc<cranelisp_backend::cache::Linker>` for cache-hit) at instantiation in `src/session_v4.rs`, with `L = ()` per Decision 35. Methods that compile, evict, or reclaim code go on the concrete `Code` / `Linker` types in the integration layer or `cranelisp-backend`, NOT on the trait — `cranelisp-types` MUST stay ignorant of `cranelift_jit::JITModule` and the linker.

**`Clone` super-bound rationale (recorded Sprint 58 Wave 3 close, originally landed Wave 3b).** The trait shape carries a `Clone` super-bound — the original Wave 1 framing of "empty marker traits" was `Send + Sync + 'static` only; Wave 3b's implementation discovered two structurally required `Clone` sites:

1. **DashMap iteration semantics.** Several read-by-value access paths through `SymbolTable.symbols` (`DashMap<Symbol, ModuleEntry<C>>`) call `.clone()` on the entry to escape the lock guard's lifetime. Without `C: Clone`, those sites would need separate clone-wrappers or unsafe lifetime extensions — the same pattern Decision 33 (single-source-of-truth on `SymbolTable`) explicitly rejected.
2. **`register_defn_signature` carry-forward invariant fix** (`crates/cranelisp-typecheck/src/program.rs:2184-2232`, Wave 3b). REPL upsert reads the existing `code: Option<C>` and clones it forward into the rebuilt entry so the carrier `Arc<Jit>` survives across the typecheck attempt — without this, mid-typecheck Arc-drop would call `unsafe free_memory()` on JIT pages still referenced by the GOT slot. The carry-forward path requires `code.clone()` to be a method on whatever `C` the integration layer chooses.

**Future-choice implications.** Every `C` and `L` choice must implement `Clone`. The constraint is acceptable: `()` is trivially `Clone`; `Code` (`src/code.rs:71`) derives `Clone` (the underlying `Arc<Jit>` and `Arc<Linker>` are cheap to clone — refcount bump, not deep copy); any future code-handle that wraps a runtime-allocated resource will naturally use `Arc`-semantics for the per-entry × per-batch many-to-many relationship (Decision 31's reclaim model rests on Arc), and `Arc<T>` is `Clone` whenever `T: ?Sized`. The `Clone` super-bound therefore codifies a property the design already implicitly requires; it is not a real future-choice constraint, just an explicit one. The blanket impl still avoids per-call-site bound annotations: any `Send + Sync + Clone + 'static` newtype satisfies `CodeStore` automatically.

Rejected alternatives: (a) put `fn drop_code(&self)` / `fn code_ptr(&self) -> *const u8` methods on the traits themselves — pulls Cranelift types into `cranelisp-types`'s contract surface (Principle 3 violation: `cranelisp-types → cranelisp-backend` is the forbidden direction); (b) use a single `C` parameter that names both code and linker — couples per-function and per-module reclaim, blocks cache-restore from supplying a `Linker` without also supplying a `Code` shape; (c) use `dyn CodeStore + dyn LinkerStore` trait objects — gives up monomorphisation, costs a vtable indirection on every code-pointer access, breaks `#[serde(skip)]` field shape (`dyn` is not `Sized`); (d) **without `Clone`** (the original Wave 1 framing) — required separate clone wrappers at every read-by-value site (DashMap iteration; `register_defn_signature` carry-forward); would have re-introduced the wrapper-proliferation pattern Decision 33's single-source-of-truth rejected and would have left no expressible way to write the Wave-3b carry-forward fix without `unsafe`. Canonical location: `crates/cranelisp-types/src/module.rs:36, :54` (trait definitions + blanket impls); concrete `Code` lives at `src/code.rs` per Decision 35. Defined Sprint 58 Wave 1; `Clone` super-bound landed Wave 3b and recorded here Wave 3 close. Rationale: Principle 3 (dependency flows toward stability — `cranelisp-types` stays method-free at the boundary) + Principle 2 (narrow interfaces — empty marker traits are the minimum surface area for "this is the per-function code store") + Principle 8 (the empty-marker-with-`Clone` shape IS the §9.1 target post-Wave-3; method-bearing or trait-object alternatives would be interim infrastructure to be removed when the integration layer's concrete types stabilise).
