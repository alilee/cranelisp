# Sprint 95: Effect-Concurrency — Complete the IO Transition (Slices 3 + 6)

**Status**: PHASE 7 CLOSE — awaiting user approval to archive + commit

**Goal**: Complete the async IO transition — make feature-on ≥ feature-off — by landing descriptor-driven async dispatch: the **token-capacity `Semaphore` pool** (slice 3) and **two-pool routing** (slice 6). After this sprint the async I/O substrate is feature-complete and correct for inferred I/O concurrency; the control layer (slices 4/5/7) and the Parallelism-axis floor/memory knot are separate subsequent sprints.

**Design note — capacity-on-token (user design review + /arch re-bless 2026-06-28).** The original "cardinality on `DefKind`" model was retired mid-Phase-3. Settled model: **capacity is a per-resource (per-token) ceiling the platform asserts, supplied dynamically as a `(token, capacity)` pair on the IO node** (`CLIO::effect_on_resource_with_capacity(token, capacity, f)` appends `capacity` at `IO_TAG_EFFECT` payload offset 32, append-only 32→40). The trampoline runs a host-owned `HashMap<token, Semaphore(capacity)>`. **Capacity attaches to the token, so distinct tokens are independent and effects sharing a token share one pool** (the DB connection-pool case). **No `DefKind`/`cranelisp-types` edge touch** (the only public-edge move is an additive, ungated `cranelisp-platform` change). `cardinality → capacity` rename; `degree` reserved for the slice-4 program throttle. See `effect-concurrency.md` §8.1/§8.2. **S95 demonstrates the pool on the BLOCKING carrier; poll-shape live capacity + acquire-around-poll → S96** (with the web rewrite, its real consumer).

## Scope

S94 completed Slice 2 (real poll-shape effect nodes suspend/resume on the reactor; two real leaves overlap ≈max on one reactor thread). But the transition landed **incomplete in one way**: feature-on, the new async path is *worse* than the old rayon path for blocking effects — blocking effects in a `Par` serialize through the single reactor thread (`join_all`) instead of parallelizing (3 RED `nt-reactor-e2e` guards). S95 completes the transition: the async substrate does everything the old rayon model did, correctly, **plus** the new resource model.

**Axis framing (user design review 2026-06-28).** `effect-concurrency.md` §3 splits two axes: **Parallelism** (fill cores with pure compute — the rayon/lenient CPU-spark path) and **Concurrency** (many blocking effects in flight, each burning no core — the reactor). The S94 floor violation (~10× slower for alloc/RC-heavy parallel work) is a **Parallelism-axis** problem (CPU sparks + atomic-RC + allocator contention), structurally orthogonal to the I/O slices. **S95 advances only the Concurrency axis.** The floor/contention knot (FIXME 0459 + the atomic-RC crux) is re-scoped to its own **S97** sprint — it neither blocks nor is blocked by slices 3/6.

**1. Slice 3 — token-capacity `Semaphore` pool (capacity-on-token model, /arch-re-blessed).**
   - **Capacity carrier (dynamic, on the node).** The platform supplies a **`(token, capacity)` pair** at the effect site via the additive `CLIO::effect_on_resource_with_capacity(token, capacity, f)` (appends `capacity` at `IO_TAG_EFFECT` payload offset 32, append-only 32→40; `effect_on_resource(token,f)` = `…(token, 1, f)`). **No `DefKind`/`cranelisp-types` edge touch, no loader lift, no got_slot** — the only public-edge move is the additive, ungated `cranelisp-platform` constructor + node-widen const (Phase-5 baseline-diff). The descriptor's static fields survive only as docs/defaults + the v6 `from_scheduling_class` bridge.
   - **Token-capacity pool.** A host-owned `HashMap<token, Semaphore(capacity)>` keyed on the node-read pair; an effect acquires its token's permit before dispatch, releases on completion. **Capacity attaches to the resource (token):** distinct tokens are independent; effects **sharing** a token share one pool (the DB connection-pool case — sum in-flight ≤ N). capacity 1 = `ResourceSerial`; N = the bounded pool; token 0 = no acquire.
   - **First-writer-wins reconciliation** (same token, different capacity): the first value sizes the semaphore, never resized; a `TokenCapacityMismatch` strand event records the disagreement (conservative — never exceeds a declared ceiling).
   - **Within-token source ordering** (`effect-concurrency.md` §8.2): capacity 1 = serial **and** source-ordered (the `SerialGroup` equivalent); capacity N≥2 = unordered N-slot bag (order guaranteed only at capacity 1).
   - **Carrier scope (user-confirmed):** S95 demonstrates the capacity pool on the **BLOCKING carrier** (`effect_on_resource_with_capacity` on blocking effects → rayon, gated by the semaphore). Poll nodes **reserve** the symmetric `(token, capacity)` slots (token @field_offset(1), capacity @field_offset(2)) at the sentinel (capacity 1); **live poll-shape capacity + the acquire-around-poll lifecycle → S96** (with the web rewrite, its real consumer).
   - **Acceptance:** N distinct-token effects overlap; N effects sharing one token of capacity N run concurrently while the (N+1)th **parks**; two **distinct** effects sharing one token share the pool (sum ≤ N); capacity-1 stays serial **and ordered**; first-writer-wins on a capacity mismatch; strand stream shows park/resume. (All on the blocking carrier; poll proves distinct-token overlap via the slice-2 mechanism.)

**2. Slice 6 — blocking/CPU two-pool routing (close the feature-on regression).**
   - The descriptor's **blocking?** field routes each effect to the correct pool: **blocking** effects → rayon (`spawn_blocking`-style), **poll-shape** (`blocking == 0`) effects → the reactor (`join_all`). The async `Par` arm partitions its branches by `blocking?` and drives both pools concurrently, joining the results.
   - This closes the 3 RED `nt-reactor-e2e` guards (`resource_serial_diff_token_parallelizes`, `auto_io_independent_diff_token_parallelizes_e2e`, `auto_io_par_grouping_uniform_across_modes`) — feature-on blocking-`Par` parallelizes again, restoring feature-on ≥ feature-off.
   - **Note:** this is a **feature-on-only** regression (production default is `concurrency-runtime` OFF, unaffected). It is "transition completion," not a production-bug fix — but the transition is not honestly complete while the gated path regresses what the old path did.
   - **Acceptance:** a mixed blocking + poll-shape `Par` overlaps on both pools (≈max not sum); the 3 guards flip green; byte-identical-off; `--link` links no executor.

## Architecture review (Phase 2)

**Verdict: SIGN-OFF WITH REVISIONS** (`/arch`, 2026-06-28). Scope coherent and correctly sequenced; revisions are clarifications + a sharpened seam, not blockers. No `cranelisp-types` edit needed this pass. Four gate rulings:

- **(a) 6-depends-on-5 is NOT real — refuted.** Two-pool routing reads the **node tag** (`IO_TAG_EFFECT` blocking vs `IO_TAG_EFFECT_POLL` poll-shape) / `poll_shape` — already on the symbol table. Slice 6 is structured fork-join (every branch joins; the existing worker-side `take_runtime_error()` → join-side `set_runtime_error()` error-ferry already covers what a supervisor would own), so it needs no supervisor (5) or backpressure (4). **Slice 6 is independent of slice 5 *and* strictly of slice 3** — co-landing with 3 is convenience (both rework the async `Par` arm), not dependency. Nothing carries to S96.

- **(b) Descriptor runtime-carrier seam ratified — split by field.** The trampoline sees only **nodes** (no symbol back-ref), so per-effect fields must reach the node:
  - **`blocking?`** → NO new carrier; already the node tag (drives routing).
  - **`token`** → already carried on `IO_TAG_EFFECT` (`FIELD_1_OFFSET`); slice 3 extends the same token onto `IO_TAG_EFFECT_POLL` symmetrically (in-process convention).
  - **`cardinality`** → the **one genuinely-new field**, carried as a **plain ungated `u32` scalar** on `DefKind::PlatformEffect` beside `poll_shape` (the exact S94 `poll_shape: bool` precedent), `#[serde(default)]` (pre-S95 cache ⇒ `0`), `0` = derive-from-`scheduling_class` (Sequential/ResourceSerial ⇒ 1 permit; Commutative ⇒ no-acquire), N≥2 = native bounded pool. Backend-baked onto the node; trampoline reads it to size the `Semaphore`. The full `ConcurrencyDescriptor` **stays `concurrency`-gated, off the public-api edge** (platform-side carrier already complete from S93 — nothing to pre-reserve). **`cardinality` lands in Phase 5 WITH its consumer (backend bake + Semaphore pool) + unit test** — NOT a Phase-2 dead reserve (a consumerless reserve would be a Principle-8 interim defect). The `_neg` frozen-edge guard stays green (a bare `u32` is not a gated type name).

- **(c) Two-pool join — compose the two existing dispatchers, wakeable bridge.** Partition the async `Par` arm by node tag: blocking branches → the **existing** rayon `dispatch_par_branches_with_trace` (already does token-grouping + error-ferry), poll-shape branches → the **existing** reactor `join_all`; top-level join the two partition-futures, merge by binding index. **Principle-8 constraint (load-bearing):** the rayon→reactor completion signal MUST be a **wakeable future** (rayon `spawn` → `futures` oneshot/channel woken via `cx.waker()`) — **explicitly forbid `block_on(rayon_join)` on the reactor thread** (re-introduces the exact starvation) and **forbid forking a third bespoke dispatcher**. That wakeable bridge is the permanent §7 cross-pool handoff reused by every later joined-pool slice. Feature-off byte-identical; `--link` no executor.

- **(d) public-API / interface impact.** `cranelisp-platform`: NO change (v7 carrier complete + gated from S93; loader extends to lift `cardinality` — int-owned, gated, off-edge). `cranelisp-types`: ONE edge touch (`cardinality: u32` on `DefKind::PlatformEffect`) — lands in **Phase 5** with the /dev change-set per baseline-diff discipline (regenerate `public-api.txt` + document at BC §7 / `interfaces.md` + unit test, atomically); `_neg` guard stays green. Node layout is an in-process backend↔intrinsics convention — **no `ABI_VERSION` bump**.
