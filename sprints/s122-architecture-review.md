## Recommendation

The closure/evaluation scope fits the existing contexts. Keep the single compiler pipeline, the existing runtime/platform split and the current embedded-agent provider membrane. No new crate, provider, service, persistence store, global publication coordinator or LLVM backend is justified.

Proceed to Phase 3 only after the user reviews the decisions below. ## Source-backed findings and corrections

1. **Reload is an unrealized consumer, not a missing producer.** `cranelisp-typecheck::instantiate_demands` is exported in `crates/cranelisp-typecheck/src/lib.rs`, implemented in `crates/cranelisp-typecheck/src/form.rs` and present in its baseline. Its contract seeds the ordinary worklist and returns `CheckResult`; stale demands become warnings. No production caller exists under `src/`. `src/redefine.rs` still captures the last `__expr`, and `session_v4/lifecycle.rs::reload_module` still appends `extra_forms`. `design/int/session-transaction.md` explicitly requires data capture before replacement and re-instantiation after reload settles. Prefer realizing that existing commitment and retiring the replay path, subject to the complete-substitution correction below. Do not add a second instantiate engine or a new typecheck API by assumption.

2. **Reload identity must use the delivered complete substitution model.** The older transaction prose says `InstanceLink { template, args }`; actual `InstanceLink` and `MonoDemand` expose `type_args`, ordered by generalized variables including result-only variables, with `from_type_args` constructors. Design must project this typed identity, including overload-arm identity, rather than reconstruct types from mangled names or function parameters. Calling `instantiate_demands` alone is insufficient: the returned bodies and ownership facts must reach normal backend compilation, staged publication, code-owner retention and existing warning handling before dependent reload continues. Source inspection does not yet establish that every required integration helper already exists; Phase 3 determines that interior composition before requesting any additional facade.

3. **The macro transfer design is still needed but contains delivered tails.** `src/marshal.rs` retains every allocation and performs the raw RC increment; `expander::invoke_clause` transfers raw trees and copies the returned Sexp without release. The +1/+2 marginal witnesses in QA's supplied evidence therefore remain meaningful known defects. The designed `intrinsics::handle` vocabulary is absent, and public consume functions still accept `i64`. However, `intrinsics/src/drop.rs` already decodes `TAG_SEXP_ANNOTATED` and has the typed private Sexp field dispatcher used by disposal. The old “missing annotated arm” prerequisite must be reconciled as delivered, with current coverage, rather than implemented twice. Immediate source-ordered macro publication is also already the current design; no revival of `PreparedMacroTurn` or unpublished GOT reservations.

4. **Macro handles and executable owners are different lifetimes.** Keep runtime reference discharge in intrinsics and macro invocation orchestration in Binary/int. The executable clause owner's lease must cover marshal transfer, protected JIT invocation and result copying/release; heap handles do not enter retained-code pools. The non-unwinding trap route must not depend on Rust destructors running in JIT frames. The existing design's consuming clause ABI pin and argument handoff need current producer-side verification; a newtype alone does not prove that JIT code consumes parameters correctly.

5. **The async session wrapper has no demonstrated product consumer.** `src/session_v4.rs::re_register_module(&mut self, &ModuleFullPath) -> Result<bool, CranelispError>` reads/parses a file, applies preamble state and queues scheduler work. Synchronous watcher reload uses `reload_module` and waits. The wrapper's located test is `tests/facade_pif_rows.rs::row_45_re_register_module_callable_on_compiler_session`, a source-text presence assertion. Recommend deleting the unused public wrapper and its obsolete facade assertion, retaining the scheduler operation used internally by reload. This removes an unnecessary unsafe orchestration choice without a publication clock. It is a proposed public surface removal, not authorized by this report. Note that `src/lib.rs` publicly exports `session_v4`: this is a Rust library surface even though the seven generated baselines do not cover the root crate. “Binary has no baseline” does not mean “not public.” If the user wants to retain embedding compatibility, the alternative is a synchronous wrapper delegating to the same reload operation, with explicit failure/skip semantics; do not silently preserve its current `bool` ambiguities.

6. **Result-root convergence is bounded.** `src/result_owner.rs::strip_io_head` and backend `lib.rs`'s result-root preparation duplicate the IO-head rule despite the delivered `ConcreteType::result_root`. Fold both consumers into their existing crate reservations. `/mem` currently samples before its `EvalResult` owner is released; fix the specified observation window in Binary/int. Neither is evidence of a new general ownership architecture defect.

7. **Platform symbol injectivity has a real static collision candidate, but reachability is not yet established.** `got_data_symbol_name("platform-x")` and the legacy platform name `hx` both lead to `__cranelisp_got_platform_hx`. The source documents this carve-out; the inspected loader constructs its names directly and did not expose the proposed name guard. That proves the naming function overlap, not a loaded-program wrong-slab defect. QA/test should establish accepted source names, loading, coexistence and linking with a minimal fixture before attribution. Do not treat broad rejection of names starting d/h/u/_ as already authorized: that would reject otherwise accepted platform names and may be much broader than the collision. Prefer a precise collision refusal at the existing load/registration boundary if the language already requires disjoint module identity; if new naming restrictions or symbol-mint changes are needed, return their exact compatibility/ABI/cache consequences to the user. A mint change would affect cached object relocations and potentially the platform ABI.

## Working REPL-agent eval slice

Place the initial runner and corpus in the existing test tooling domain, for example `tests/scripts/` plus a small fixture directory. Test owns executable runner/grader artifacts; QA owns task-selection and measurement policy; Binary/int design owns only any proven production seam gap. This is a process client of the actual agent-enabled executable, not a second agent implementation or a new compiler mode.

Reuse the isolated `target/agent` build convention from `run-agent-lane.sh`; it currently launches deterministic agent e2e tests and is not itself a live eval runner. Capture the actual executable path/hash, compiler revision, feature/configuration set, provider/model/endpoint, prompt and starting fixture hashes, primer stamp, run limits, timestamps, process status and terminal outcomes. Fresh temporary projects/sessions and fixed caches/prelude configuration prevent residue from one task being mistaken for competence in another. Use the existing `CRANELISP_AGENT_LOG`, `CRANELISP_AGENT_TRACE` and scenario stamp. Logs append and deliberately swallow sink failures, so the harness must verify the selected observation artifacts exist and are parseable if it relies on them; no new production logging reliability promise is needed.

Start with the documented real `safe-dial` task and the smallest additional actual recovery/compiler-use sessions QA selects. Evaluate committed definitions and task outputs through explicit subsequent REPL commands or the ordinary compiled artifact, not the agent's claim of success. A deterministic stub run should prove that the harness correctly classifies success, wrong result, refusal and process failure; its output is harness evidence, never a live model-quality baseline. Store repeated live outcomes separately from compiler defects and provider/transport errors. Cost/tokens are optional when not actually supplied by existing telemetry; report unknown rather than inferred precision.

`provider.rs` currently supports Anthropic, Ollama and stub; no OpenAI adapter is implied by the delivery-role model allocation. A live run needs user-selected provider/model/endpoint, allowed fixture data disclosure, autonomy/consent mode and bounded run budget. Per-request max tokens are currently a fixed 65,536; a time limit is not an exact spending cap. Before selecting a paid provider, decide whether the existing request/step limits meet the approved budget or whether a small Binary/int configuration change is required. Record repeats and request settings; model nondeterminism cannot be eliminated by a prompt hash. No automatic tuning, provider comparison service or perfect-score release gate is required.
