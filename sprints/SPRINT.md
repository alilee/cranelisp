**Goal**: Get `cranelisp-platform` into clean, green, fully-shaped end state: audit drained (F1–F9 closed), new platform-boundary API surface authored and implemented inside the crate (`CLAdt` + field-traversal + `ABI_VERSION` + grown `HostCallbacks`), and `facades/platform.md` retired by folding into source rustdoc + `bounded-contexts.md` §5 — the 3rd data point of the facade-retirement pattern. ## Background

Sprint 71's original cleanup scope (audit-driven facade-editorial corrections F1–F9) paused at Phase 2 review when the user surfaced a deeper facade defect: **platform fn type signatures use a parallel grammar** parsed by a custom ~110-line parser in `int/src/platform.rs::parse_type_sig` that accepts only `{Int, Bool, Float, String, IO, Fn}`. The language's own type-expression machinery is not engaged. Fixing this needs a coordinated host-side change: route sig parsing through `cranelisp-frontend` + `cranelisp-typecheck`, register platforms as normal modules, cache through `.meta.json`, add a `/abi` REPL command.

That host-side work is deferred. **This sprint focuses solely on `cranelisp-platform`** — design the new platform-boundary API surface, implement it inside the crate so future host-side work has a settled target to wire against, and retire the facade.

## Architecture inside `cranelisp-platform` (target this sprint)

1. **`ABI_VERSION: u32` constant** in `cranelisp-platform`. The field-traversal protocol version. DLLs publish the version they were built against; host (future sprint) rejects mismatched DLLs.

2. **`CLAdt<T: CLAdtType = AnyAdt>` wrapper type** joining the `CLInt`/`CLBool`/`CLFloat`/`CLString` family. `#[repr(transparent)]` over `i64` + zero-sized `PhantomData<T>` (the transparent-repr rule is preserved by the zero-sized phantom). Implements `CLHeap` so it composes with `CLOwned`. The generic parameter `T: CLAdtType` carries the static type-name binding (e.g. `CLAdt<Rectangle>` where `Rectangle` is a marker type with `const TYPE_NAME: &'static str = "Rectangle"`). Field access methods drop the runtime type-name argument because `T::TYPE_NAME` is known at compile time:

   ```rust
   pub trait CLAdtType { const TYPE_NAME: &'static str; }
   pub struct AnyAdt;
   impl CLAdtType for AnyAdt { const TYPE_NAME: &'static str = ""; }

   #[repr(transparent)]
   pub struct CLAdt<T: CLAdtType = AnyAdt>(i64, PhantomData<T>);

   impl<T: CLAdtType> CLAdt<T> {
       pub fn read_tag(&self) -> u32;                              // fixed offset 0
       pub fn read_field<F: CLType>(&self, field_name: &str) -> F; // schema lookup uses T::TYPE_NAME
       pub fn own_field<F: CLHeap>(&self, field_name: &str) -> CLOwned<F>;  // inc-on-read for heap fields
   }
   ```

   DLL author writes `extern "C" fn rectangle_area(r: CLAdt<Rectangle>) -> CLInt { r.read_field::<CLInt>("w") ... }`. The `Rectangle` marker type is auto-generated by `declare_platform!` from the schema declaration. Type-witness mismatch handling (panic vs Result) and construction shape (return-value path) are /design platform decisions for Phase A.

   `CLAdt<AnyAdt>` is the untyped fallback (default parameter) for generic walking — methods either accept it with a runtime type-name argument via a `read_field_named` variant, or panic with "untyped CLAdt; cast to typed first." /design platform settles the exact shape of the untyped escape hatch.

3. **`HostCallbacks` grows minimally** — by **two nullable fn-pointer fields** (final shape settled in Phase A):
   - `alloc_with_tag` — host-side allocator entry point for ADT construction in DLL return paths. Required only by construction; read paths are schema-driven and callback-free.
   - `validate_schema` — host-side validator called at DLL load: "DLL's shipped schema vs cranelisp's actual deftype data — agree?" Stubbed null this sprint (load succeeds without validation); populated future sprint when typecheck wiring lands.

   **Read paths take ZERO new HostCallbacks** because field-offset lookup is performed by the DLL itself against its parsed-at-init schema (the schema travels with the DLL). The marker-type pattern + DLL-local schema makes read access purely in-DLL — no FFI round-trip per `.read_field()` call.

   The struct addition is a wire-level change — DLLs see the new fields; the host must populate them. **Host-side population is deferred**; `int`'s `HostCallbacks` initializer site adds `null` pointers for both new fields with a `// FIXME(NNNN)` comment. CLAdt **construction** methods panic on null `alloc_with_tag` until wired (R1 gate applies). Read methods do not panic — they're callback-free. That null-pointer patch is the **only** consequential change to `int` this sprint.

4. **Audit findings dispositioned in line with the new shape.** F1, F3, F4, F5, F6, F7 close as the rewritten/folded narrative captures their corrections. F2 is a source-move (delete `impl Default for HostContext` per consumer-search at Phase 2 walkthrough — zero callers anywhere). F8, F9 stay no-action.

5. **Schema format + marker-type pattern** — the simple representation the future `/abi` emitter will produce, settled this sprint. The schema is a **cranelisp S-expression string** describing the types a DLL works with:

   ```
   ((Point ((CLInt x) (CLInt y)))
    (Rectangle ((CLInt w) (CLInt h)))
    (Bounds ((Point tl) (Point br)))
    (OptionInt None (Some ((CLInt val))))
    (ListInt Nil (Cons ((CLInt head) (ListInt tail)))))
   ```

   Form: `(TypeName ((FieldType field_name) ...))` for products; `(TypeName Variant1 (Variant2 ((FieldType field_name) ...)) ...)` for sums. Field types name CL wrapper types (`CLInt`, `CLString`, etc.) or other declared ADTs in the same schema.

   The `declare_platform!` macro grows a `schema:` arm. From that schema, the macro auto-emits:
   - **Marker types** — one zero-sized struct per declared type, implementing `CLAdtType` with `TYPE_NAME` set to the cranelisp name. DLL authors get `Rectangle`, `Point`, `OptionInt`, `ListInt` etc. for free.
   - **A static `Schema`** — `LazyLock`-initialized at first use; parsed once; ambient to all CLAdt method calls inside the DLL via a per-DLL trampoline `cranelisp-platform` resolves through.

   How `read_field` resolves at runtime: `CLAdt<Rectangle>::read_field::<CLInt>("w")` looks up `T::TYPE_NAME = "Rectangle"` + `"w"` in the parsed `Schema`, computes the byte offset from declared field positions (tag at 0, fields packed at sequential 8-byte slots per CLType size), transmutes at that offset. Pure in-DLL — no HostCallback. The schema parse cost is one-time per DLL init; per-call cost is one hashmap lookup + linear walk of a small field list.

   **No sophisticated Rust macro (e.g., typed-newtype generator with baked offsets) in this sprint** — the marker-type pattern + schema-driven runtime lookup is sufficient ergonomics, and leaves the door open for layer-2 work later: a sophisticated proc macro could consume the same schema to emit typed-newtype wrappers with baked offsets if and when measurement shows runtime lookup is friction; or a thin `AdtView` runtime helper could provide additional sugar without a new macro. Both layer-2 options consume the schema this sprint settles.

   The schema format lands in the rewritten rustdoc + BC §5 with worked examples covering products, sums, polymorphic instantiations, and recursive shapes. Executable test-fixture examples in `cranelisp-platform`'s own tests prove the schema parser + marker-type pattern + CLAdt walker compose end-to-end against synthetic heap layouts.

6. **Facade retired.** `facades/platform.md` folded into `crates/cranelisp-platform/src/lib.rs //!` preamble + per-item `///` rustdoc + `design/arch/bounded-contexts.md` §5. The narrative covers: the C-ABI ground-truth (PlatformFn, PlatformManifest, declare_platform! macro with the new `schema:` arm); the host-side wrapper family (CLInt/Bool/Float/String/IO/Owned, plus the generic `CLAdt<T>`); CLHeap + RC discipline (Decisions 0013, 0024); the marker-type + schema pattern (item 5); ABI versioning; the **future** sig-grammar+platform-as-module story stated as forward-looking commitment with a clear "not yet implemented; see FIXME NNNN" marker. Cross-references in other facades, sequence diagrams, principles, decisions register swept. 3rd data point in the facade-retirement pattern (after `facades/types.md` S69 Sub 42 and `facades/frontend.md` S70 B3-C).

## Architecture review (Phase 2)

**Verdict: PASS WITH REVISIONS — apply revisions below, then Phase 3 may begin.**

Reviewer: `/arch`, 2026-05-27 (re-fire against Reading-3 + facade retirement + DSL design scope; supersedes the earlier verdict against the cleanup-only scope).

### Scope coherence verdict — PASS with one carve-out

The platform-crate-only-plus-null-pointer-patch scope is coherent and designable in isolation, with one carve-out called out below (CLAdt field-traversal). The new surface (`ABI_VERSION` const, `CLAdt` wrapper joining the CLInt/CLBool/CLFloat/CLString family, `HostCallbacks` growth, DSL spec) is internally self-contained at the crate edge: no item in this surface forces a `cranelisp-types` addition (FQTypeName remains zero-hits in platform per `facades/platform.md` §"FQTypeName migration (Decision 47)"; the layout-lookup key, when wired host-side in a future sprint, lives on `HostCallbacks` as opaque to platform). The sole non-platform edit — the `int`-side `HostCallbacks` initialiser appending null pointers for the new fields with a FIXME comment — is a one-line change that does not pierce any other crate's surface and respects the bounded-context allocation in `bounded-contexts.md` §5 ("DLL lifecycle and retention" is int's; the host callback population is also int's).

**The carve-out — field-traversal is not fully designable in isolation.** `CLAdt::read_field<T>(&self, name: &str) -> T` requires a heap-layout lookup keyed by name. Without typecheck-side layout registration (the deferred host-side wiring), there is no in-tree population path; methods that depend on it MUST panic on null-callback. That panic-on-null mode is acceptable interim *only if* the panic message is precise (names the field, the type, and the missing-callback FIXME) and *only if* the user-reachable surface (the platform-DLL author writing against `CLAdt`) cannot be reached in this sprint's test surface except through synthetic test fixtures the crate itself constructs. Both conditions are satisfiable. Detailed risk assessment in §"Interim-architecture risk" below.

### DSL design separability — PASS

The Rust-mirror DSL spec can be settled this sprint without the `/abi` emitter being built. The hand-written DSL examples committed as `cranelisp-platform` tests are sufficient to validate the spec composes with `CLAdt` end-to-end, *provided* the test-fixture heap layouts are synthesised in-test against the exact `[tag | field_0 | field_1 | ...]` byte shape `CLAdt` will read. The emitter-being-deferred does NOT leave critical spec questions unresolved because the spec's binding choices (representation; polymorphism; tag encoding; RC discipline; recursion) are settled at the spec level by the test examples — the emitter's only future-question is "given a `deftype` form, deterministically produce text matching the spec," which is a code-generation problem, not a spec design problem. Risk: if the DSL spec turns out to require information available only at typecheck time (e.g., the resolved concrete variant types for a polymorphic instantiation), the spec might force an emitter-side typecheck dependency that surprises the future sprint. Mitigation in arbitration 7 below: rule for the typed-newtype-only + concrete-instantiation form, which is reachable from the `deftype` syntactic form alone (no typecheck context needed).

### Arbitrations (7 items)

**A1 — `CLAdt` type-witness mismatch handling: PANIC, not Result.**

Ruling: `read_field::<T>` and `own_field::<T>` panic on type-witness mismatch with a message naming the field, the asserted type, and the actual heap-layout entry's stored type. *Grounding*: Principle 14 (FFI boundary types are governed by layout discipline) — the ABI is layout-versioned, so a mismatch at this boundary is binary-incompatibility-with-`ABI_VERSION`, not run-time-data-malformed. A DLL author calling `read_field::<CLInt>("x")` where the layout records `x` as a heap field has either built against a stale `ABI_VERSION` (which `load_manifest` should have refused upstream) or has written wrong code; both are programmer bugs. *Grounding*: Principle 06 (complexity has a budget) — `Result` adds a `?`/`unwrap` per access at every DLL-author call site for a condition that, by ABI-version invariant, cannot occur in correctly-built DLLs. The host-side surface-to-user concern is resolved at a different layer: the host (in a future sprint) catches the panic at the FFI trampoline boundary and surfaces a clean `PlatformError::DispatchError` to the user — i.e., the surface-to-user transformation is a host-side concern, not a wrapper-API concern.

**A2 — `CLAdt` construction shape: DEFERRED to Phase A `/design platform`** — with constraints.

Constraints: (i) construction MUST NOT require the host to be wired (this sprint ships with stubbed-null callbacks); construction at minimum needs `HostCallbacks::alloc_with_tag` (or equivalent — possibly two callbacks, see A3) which is one of the deferred fields. So either construction is *itself* a panic-on-null-callback method, or construction belongs to the future host-wiring sprint. /design platform proposes which; (ii) the chosen shape MUST compose with `CLOwned<CLAdt>` (the wrapper-family-uniformity invariant); (iii) the chosen shape MUST be expressible from the DSL spec — i.e., a `Rectangle::new(tl, br)` typed-newtype constructor (per A7's ruling) maps cleanly to whichever shape /design picks. Builder vs direct-constructor is a /design platform call; the BC §5 invariant set does not constrain it.

**A3 — `HostCallbacks` growth granularity: SHRINKS TO TWO NULLABLE FIELDS** (post-marker-type pattern revision 2026-05-27).

The marker-type + DLL-local-schema pattern eliminates the need for host-side field-layout callbacks. The DLL parses its own schema at init, computes offsets locally, performs reads via offset-transmute without round-tripping to the host. The only growth required:

- `alloc_with_tag: extern "C" fn(tag: u32, field_count: u32, field_sizes_ptr: *const u32) -> i64` — host-side allocator entry for ADT construction in DLL return paths.
- `validate_schema: extern "C" fn(schema_ptr: *const u8, schema_len: usize) -> bool` — host-side validator called at DLL load to verify DLL's schema matches cranelisp's actual deftype data. Stubbed null this sprint.

Both are raw `extern "C" fn` per Principle 14. Final exact signatures (including out-parameters for error reporting) and the null-policy (per A6) are /design platform's call; the count is fixed at two.

*Grounding*: Principle 6 (complexity has a budget) — the per-primitive-callback growth + type-id-tag-machinery sketched in the pre-revision A3 was redundant once the DSL pattern was reframed (schema-driven runtime lookup → DLL-local schema → no host round-trip for reads). The simpler shape eliminates an entire class of cross-FFI dispatch logic that would have needed both build and validation.

**A4 — `ABI_VERSION` bump policy: BUMP ON ANY LAYOUT-AFFECTING CHANGE TO ANY `#[repr(C)]` STRUCT OR ANY CONST-VALUE THE DLL READS BY HARD-CODED OFFSET OR CONST-EXPECTATION.**

**A8 — Sum-type field lookup discipline: DEFERRED to Phase A `/design platform`** — with constraints.

For a sum type with variant-scoped fields (e.g., `(OptionInt None (Some ((CLInt val))))`), `read_field::<CLInt>("val")` requires the schema lookup to resolve which variant's `val` is meant. Two options:

- **(a) Unqualified with auto-walk-all-variants**: lookup searches all variants for a field named `"val"`; unique match → use it; ambiguous → panic naming the ambiguity. Simpler call-site syntax; works for the common case (variants with distinct field names); fails noisily on shared names.
- **(b) Dot-qualified**: `read_field::<CLInt>("Some.val")` — caller specifies the variant. Verbose but unambiguous. The DLL author already knows the variant from `read_tag` dispatch; the qualifier mirrors that knowledge.

Constraints: (i) the rule MUST be uniform — pick one, not contextual; (ii) the rule MUST work for the worked examples in the test surface; (iii) the rule SHOULD compose with the future layer-2 ergonomic helpers (e.g., a `match-on-tag` macro might benefit from one shape over the other). /design platform settles; both shapes are achievable in Phase A.

**A6 — `HostCallbacks` null-pointer policy: STABLE NULL with runtime check in CLAdt methods.**

Ruling: the new fields are `extern "C" fn` pointers (not `Option<unsafe extern "C" fn ...>`). At `HostCallbacks` construction in `int` (the null-pointer patch), the fields are populated with `null_callback_for_field_traversal` etc. — a small set of named null-callback functions defined inside `cranelisp-platform` (`pub extern "C" fn null_callback_alloc_with_tag(...) -> i64 { panic!("HostCallbacks::alloc_with_tag not wired; see FIXME NNNN") }`). CLAdt methods that depend on a callback check `is_null` against the pointer in `HostContext::callbacks.load()` and panic with a specific message; alternatively, the named-null-callback approach lets the panic come naturally from the callback body without an extra null check at every CLAdt method call site. /design platform picks one of these two (both satisfy the constraint). *Grounding*: Principle 14 — `#[repr(C)]` ABI fields are raw `extern "C" fn` pointers, not Rust-typed `Option<fn>` (which has no stable C-ABI layout); Principle 18 — the named-null-callback approach is structural ("the field is always non-null; null-state-is-not-representable"), the runtime-check approach is behavioral. Either is acceptable per the principle's "when both options exist" framing; the named-null-callback approach is slightly preferred but not binding.

**A7 — Rust-mirror DSL representation: MARKER-TYPE PATTERN with cranelisp-S-expr schema** (re-ruled 2026-05-27, superseding the prior typed-newtype-with-baked-offsets ruling).

The DSL splits into two layers, only layer 1 in scope this sprint:

**Layer 1 (in scope this sprint) — Schema format + marker-type pattern.** The schema string (item 5 of §"Architecture") is the simple representation `/abi` will eventually emit. It informs runtime field lookups via the DLL-local parsed-Schema. The `declare_platform!` macro auto-emits marker types from the schema; DLL function signatures use `CLAdt<MarkerType>` for typed parameters; field access is `r.read_field::<CLInt>("w")` — the type-name comes from the marker via `T::TYPE_NAME`. Polymorphic ADTs are mapped to concrete instantiations (`OptionInt` not `Option<CLInt>`) — the cranelisp typecheck has already monomorphised at the language level; the schema mirrors that decision.

**Layer 2 (deferred — future work, NOT in scope this sprint).** What ergonomic surface DLL authors get on top of layer 1. Options to be settled later by measurement:
- (i) **Typed-newtype generator** — a sophisticated proc macro consuming the schema to emit `pub struct Rectangle { inner: CLAdt<RectangleMarker>, ... }` with named-field accessor methods carrying baked offsets and per-field witness types. Trades schema-runtime-lookup for build-time codegen complexity.
- (ii) **Runtime `AdtView` helper** — a thin host-side wrapper providing additional sugar (e.g., `match-on-tag` macros, field-name-not-found helpers) without a new macro.
- (iii) **Stay with layer 1** — if measurement shows the verbosity is acceptable and the schema-lookup cost is negligible (likely for non-hot platform fns).

The layer-1 choice settled this sprint does not foreclose any layer-2 option — all three consume the same schema. The choice between them is /design platform's call in a future sprint, gated by usage data from real platform DLLs.

Worked examples for the three forms in scope (all marker-type pattern, layer 1):

- **`(Rectangle [:CLInt w :CLInt h])` — product type.** Schema declares `(Rectangle ((CLInt w) (CLInt h)))`. Macro emits `pub struct Rectangle; impl CLAdtType for Rectangle { ... }`. DLL author writes `pub extern "C" fn rectangle_area(r: CLAdt<Rectangle>) -> CLInt { let w = r.read_field::<CLInt>("w"); let h = r.read_field::<CLInt>("h"); /* ... */ }`. Per-type inherent-impl available — `impl CLAdt<Rectangle> { pub fn area(&self) -> CLInt { ... } }` if the DLL author wants helpers.

- **`(Bounds [:Point tl :Point br])` — nested heap fields.** Schema declares `(Bounds ((Point tl) (Point br)))`. Macro emits markers for both `Bounds` and `Point`. Author writes `let tl: CLOwned<CLAdt<Point>> = b.own_field::<CLAdt<Point>>("tl");` — the `F: CLHeap` witness on `own_field` is the typed `CLAdt<Point>`, so the returned `CLOwned` is typed. Nested access reads `tl.read_field::<CLInt>("x")`. F1 stays "remove speculative `into_inner`" — no `into_inner` needed for this design.

- **`(OptionInt None (Some [:CLInt val]))` — sum type, concrete polymorphic instantiation.** Schema declares `(OptionInt None (Some ((CLInt val))))`. Macro emits the `OptionInt` marker + (optionally; /design platform decides) a `#[repr(u32)] pub enum OptionIntTag { None = 0, Some = 1 }` derived from variant declaration order. Author writes `match opt.read_tag() { 0 => /* None */, 1 => opt.read_field::<CLInt>("val"), _ => unreachable!() }`. Tag-as-Rust-enum is /design platform's call; either way the `read_tag` call returns u32 and the DLL author dispatches on it.

- **`(ListInt Nil (Cons [:CLInt head :ListInt tail]))` — recursive sum, polymorphic instantiation.** Schema declares `(ListInt Nil (Cons ((CLInt head) (ListInt tail))))`. Marker emitted; recursion natural via `own_field::<CLAdt<ListInt>>("tail")`. Iterative walker pattern works: `let mut node = ...; loop { match node.read_tag() { 0 => break, 1 => { total += i64::from(node.read_field::<CLInt>("head")); node = node.own_field::<CLAdt<ListInt>>("tail").into_inner(); /* — or whatever construct /design platform settles for re-binding the typed wrapper from the owned heap reference */ }, _ => unreachable!() } }`.

Sum-type lookup discipline (qualified `"Some.val"` vs unqualified `"val"`) deferred to /design platform per the constraint set above.

*Grounding*: Principle 6 (complexity has a budget) — marker types + DLL-local schema cost less than typed-newtype-with-baked-offsets emission, and leave layer-2 ergonomic refinement to a future sprint gated by usage data; Principle 14 (FFI layout discipline) — `CLAdt<T>` is `#[repr(transparent)]` with `PhantomData<T>` zero-sized; the FFI ABI is the inner `i64`; the marker type is a host-side typing convenience invisible to JIT-emitted calling code; Principle 15 (facade types live with behavior) — the marker-type pattern's surface (the `CLAdtType` trait, the `CLAdt<T>` generic, the `declare_platform!` macro arm) all live in `cranelisp-platform` alongside the behavior; Principle 18 (structural invariant) — type-name binding from marker type to runtime schema lookup is enforced by the type system at every method call site.
