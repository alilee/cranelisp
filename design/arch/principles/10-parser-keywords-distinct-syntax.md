# Principle 10 — Parser keywords are for distinct syntax only

**Statement.** The AST builder recognizes a form as a special form (building a distinct `Expr` variant) only when its syntax differs from a function call — i.e., its arguments cannot be parsed as expressions.

**Rationale.** A name in scope is the module system's authoritative answer to "what does this form mean?" Parser-level special-casing pulls authority out of the module system into the frontend, where it is harder to introspect, override, or remove.

**Consequence.** `(let [x 1] body)` MUST be a parser keyword because `[x 1]` is a binding vector, not a Vec literal. `(if c t e)` MUST be a parser keyword because it has short-circuit semantics that require a distinct AST node. But forms with regular call syntax — `(platform "name")` — SHOULD flow through the module system as ordinary names. New special forms added in later rings default to the module-scoped approach unless they genuinely need distinct syntax.

**Two categories of special form.** A *special form* is a form the **parser / AST-builder and the typechecker** treat specially — it lowers to a dedicated `Expr` variant (recognised before any name lookup runs) and is dispatched in inference by that variant rather than by resolving a callee. This Principle's "distinct syntax" criterion governs whether a form earns that special treatment. Among the forms that do, there are two scoping categories:

- **Root special forms** — always available, **no import, no module path**. `defn`, `deftype`, `deftrait`, `defmacro`, `let`, `if`, `match`, `do`, `fn`, and **`trace`** are root special forms. They are not entries in any module; they are recognised by the parser/expander and lowered to AST nodes (`Expr::Let`, `Expr::If`, `Expr::Trace`, …) before resolution. A root special form's name is therefore **reserved**: user code cannot define or bind it (`(defn trace …)`, `(let [trace …] …)`, `(fn [trace] …)` are rejected outright — not allowed-but-shadowed), because the parser would never see the name as an ordinary symbol and a silent shadow would be a latent footgun.

- **Module-scoped special forms** — special-cased by the parser but *named within a module*, requiring import to reach by short name. This is the S20-era category `(trace …)` originally inhabited. **As of 2026-06-04 this category is empty**: `trace` was the last member, and the user's ruling reclassified it as a root special form. The category remains describable (a later ring could reintroduce one) but has no current member — which is itself architecturally clarifying: every form the parser special-cases today is root-scoped, so "special-cased by the parser" and "always available without import" currently coincide.

**`(trace expr)` — root special form (user ruling 2026-06-04, superseding the S20 framing).** `(trace expr)` has regular call syntax, so this Principle's default would route it through the module system as an ordinary name. The as-built compiler instead recognises `trace` as a special form producing a distinct `Expr::Trace` node, because the form carries two non-call semantics the "arguments parse as expressions" test does not capture: the body value is **discarded** (only the recorded call tree is returned) and the static type is **always `Trace`** regardless of the body's type. The **as-built recognition conforms** to the target — `build_trace` (`ast_builder.rs:991/1036`) emits `Expr::Trace` and `infer_trace` dispatches on the variant; the change to root-scoped status is near-zero code (the recognition family is unchanged; what changes is the spec terminology and the addition of reserved-name enforcement). The user accepted this as "the trace node" and ruled it **root-scoped and reserved**.

**Form/ADT asymmetry (deliberate).** The keyword `trace` is root-scoped and needs no import; the `Trace` / `TraceCall` types and their field accessors (`name`, `params`, `result`, `children`, `nanos`) are **module-scoped `primitives` entries that DO require import** (or qualified names) to destructure a returned trace. The two halves are governed differently on purpose — this mirrors the existing `Sexp`-in-`macros` precedent (quasiquote works without import because the expander emits qualified constructors; bare `Sexp` constructors need the import). Spec §3.2.4 states the asymmetry explicitly.

**Evolution (S20 → 2026-06-04).** `(trace …)` was introduced at S20 as a Ring-4 *module-scoped* special form, and the tension between "regular call syntax" and "parser special-casing" was the genesis of this Principle. A prior pass recorded `trace` as a standalone "keyword exception" to the module-system default. The 2026-06-04 user ruling resolved the framing cleanly: `trace` is a **root** special form — the same recognition family as `defn`/`let`/`if`/`match`, always available, reserved — which retired the standalone-exception framing and emptied the module-scoped-special-form category.
