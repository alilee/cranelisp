# Adapt facade-compliance test for retired `facades/types.md`

## Issue

S69 Phase 3 Submission 42 retired `design/arch/facades/types.md` as a permanent document. Substance migrated to source-side homes:

- Crate-root `//!` rustdoc narrative in `crates/cranelisp-types/src/lib.rs`
- Per-item `///` docstrings (already extensively present from the S69 walk-through; reconfirmed at retirement)
- Cross-type design narrative in `design/arch/bounded-contexts.md` §7 (visibility-vs-form-records distinction, multi-legged authoring table, macro/trait-impl placement, FQTypeName binding, BC invariants)
- Public surface enumeration: already in `crates/cranelisp-types/public-api.txt` (auto-generated by `cargo public-api`)

The existing per-crate facade compliance test (`tests/facade_compliance.rs`, S67 Wave 0) asserts that every pub-api line in `crates/cranelisp-types/public-api.txt` is named in `design/arch/facades/types.md`. That assertion is now meaningless for `cranelisp-types` because the facade no longer exists.

## Proposed resolution

Two options for /qa's call:

**(a) Disable the test for cranelisp-types specifically.** The other per-crate facade compliance tests stay; only the `cranelisp-types` slice retires. Cheap mechanical change; surface gating still works through the `public-api.txt` baseline diff at PR time per `design/arch/CLAUDE.md` §"Baseline-diff discipline".

**(b) Replace with rustdoc-coverage assertion for cranelisp-types.** Every pub item in `crates/cranelisp-types/public-api.txt` MUST have a `///` doc comment present in source. This is the manifestation-site equivalent — the rustdoc IS the documentation, and the test enforces it stays present even as items are added. Stronger guarantee than (a); aligns with the "source IS the facade" model adopted for cranelisp-types.

(b) is preferred per the manifestation-site principle (the rustdoc is where a future reader expects to find the per-item documentation; the test enforces it stays present). Either way is /qa's call; this FIXME is the request.

## Operational implication / Context

- **Surface gating remains intact.** The `public-api.txt` baseline diff at PR time still gates the cranelisp-types public surface; nothing in the facade retirement changes that. The compliance-test pivot is about the per-crate "is every pub item documented in the right place" check, not about the surface itself.
- **Other per-crate facades.** `facades/backend.md`, `facades/intrinsics.md`, `facades/primitives.md`, `facades/typecheck.md`, `facades/int.md` remain in place; their per-crate compliance tests continue unchanged. `facades/frontend.md` joined `facades/types.md` in retirement at S70 Phase B group B3-C, and `facades/platform.md` followed at S71 Wave 4 — the same source-rustdoc-IS-the-facade model applies to all three retired (compliance assertion shifts to per-item rustdoc presence per option (b)). Whether the remaining five follow is a separate decision per crate.
- **Sprint artifact `types-audit-s69.md` is retained** at `design/arch/facades/types-audit-s69.md` as historical reference (the walk-through reasoning record). Not the compliance-test target.
- **Reference for the source-side narrative**: `crates/cranelisp-types/src/lib.rs` `//!` block + `design/arch/bounded-contexts.md` §7.
